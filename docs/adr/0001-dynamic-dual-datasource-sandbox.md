# ADR 0001: 基于双域名与物理双库的自由体验沙箱及动态路由架构

- **状态**: Accepted (已采纳)
- **日期**: 2026-11-18
- **决策者**: 研发团队 / 系统架构师

---

## 1. 背景与问题陈述 (Context)

中学班主任工作平台当前仅在生产环境（Prod）单实例运行，无独立测试服务器。为了向潜在使用者、学校领导及教师提供功能演示与试用体验，系统需要开放免门槛的体验通道。

在初始规划中曾考虑“单库逻辑隔离（在同一库内通过 `user_id` 过滤演示数据）”，但经过深度推敲，该方案暴露了显著的架构隐患：
1. **正式生产数据误伤风险**：在单库下进行定期全量数据清空，哪怕代码存在极微小的一行漏写 `WHERE user_id = :uid`，都可能导致生产真实教师和班级数据被毁灭性清空；
2. **后期扩展维保成本高**：后期业务迭代新增数据表或子表时，若开发人员遗漏在清理列表中注册，或子表未冗余 `user_id`，会导致演示重置遗留脏数据与外键冲突；
3. **过度工程化与权限束缚**：为了防止访客改密码或破坏管理后台，单库模式需在业务层编写大量防御性拦截逻辑，导致体验者无法体验完整管理功能，违背了简洁（KISS）原则。

因此，亟需一种**在物理层面彻底杜绝误伤正式生产数据、免去权限束缚、且不增加额外服务器部署成本**的高可用架构。

---

## 2. 决策详情 (Decision)

我们决定采用**“双域名 + 独立物理双库 + 原生动态数据源路由 + 自由体验沙箱”**架构：

### 2.1 物理双库与双域名拓扑
- **正式环境 (Prod)**：生产域名（如 `teacher.yourdomain.com`）指向正式库 `teacher_workspace`，数据持久稳定，不参与任何重置；
- **测试/演示环境 (Dev/Demo)**：演示域名（如 `demo.yourdomain.com` 或 `dev.yourdomain.com`）指向独立测试库 `teacher_workspace_demo`；
- **单进程与单构建产物**：同一个 Spring Boot 后端进程（8088）同时接入两个数据源；前端产物仅构建一次，Nginx 双 Server 块统一反代。

### 2.2 数据源动态路由实现 (Zero-Dependency KISS)
- 放弃引入第三方复杂组件，采用 Spring 原生内置的 `AbstractRoutingDataSource` + `ThreadLocal<String>` 机制；
- 业务层全系统 30+ 个直接依赖 `JdbcTemplate` 的 Controller 与 Service **保持 100% 零修改**；
- 前端在 `http.js` 请求拦截器中依据当前访问域名（包含 `demo` 或 `dev`，或本地调试参数 `?env=demo`）自动在 HTTP Header 附加 `X-Datasource: demo/master`；
- 后端拦截器依据 Header 与 Host 动态绑定当前线程数据源，并在请求结束时 `clear` 自动回退正式库。

### 2.3 自由体验沙箱机制 (Unrestricted Demo Sandbox)
- 测试库因具备物理隔离屏障，**彻底解除对演示账号的权限拦截与防御限制**；
- 访客在演示域名下直接以管理员（`admin / 123456`）一键秒进，全功能开放（包含用户管理、系统配置、成绩录入、改座次、改密等）；
- 无论访客如何增删改，影响范围完全限制在测试库内。

### 2.4 测试库 7 天重置与高保真数据灌装
- **重置周期**：每 7 天自动重置一次（固定在每日凌晨 04:00 低峰期由单线程检查执行）；
- **手动恢复**：前端全局顶部常驻黄色醒目测试横幅，支持访客随时点击“一键恢复初始数据”；
- **并发与防刷防护**：重置过程加本地 `ReentrantLock` 互斥锁，接口设置 5 分钟操作冷却时间；
- **高保真灌装**：将原 `seed.mjs` 中的真实体验数据（50 名学生名册、周课表、男女交错座位表、值日轮值、两次考试对比成绩、待办事项、沟通记录及宠物）在 Java 端移植为 `DemoDataSeeder`，重置后自动将密码刷回 `123456`。

### 2.5 数据库生命周期管理
- 不引入 Flyway，避免存量生产库的 baseline 风险与多数据源集成复杂度；
- 沿用当前经过生产验证的 `schema.sql + DataInitializer` 模式做轻量幂等建表与字段迁移。

---

## 3. 架构影响与权衡 (Consequences)

### 积极影响 (Positive)
- **绝对的生产安全性**：正式生产库与演示测试库在数据库连接层面彻底隔离，重置代码绝不触碰正式库连接，误伤生产概率降为 0；
- **零后期维护负担**：后期迭代新增任意表，演示库重置均可一并全量初始化，无需担心漏配表名或无 `user_id` 关联问题；
- **极致纯粹与高性能**：原生 Spring 实现不引入任何额外第三方 jar 包冲突，运行开销几乎为零；
- **极佳的用户试用体验**：访客开箱即见生动饱满的 50 人教学图表，并拥有不受限制的完全控制权。

### 潜在代价与妥协 (Negative & Trade-offs)
- MySQL 实例需多分配一个数据库存储空间（演示库仅占几兆微小空间，可忽略不计）；
- 线上部署时 Nginx 需要配置两个域名或二级域名的反向代理规则。
