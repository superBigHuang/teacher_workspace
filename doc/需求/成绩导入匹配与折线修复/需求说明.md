# 成绩导入匹配规则 + 折线图请求死循环修复

## 背景与问题

1. 导入成绩弹窗的文件按钮文字被弹窗宽度截断（"表头：学号|姓名|科…"看不全），用户不知道表头格式与匹配规则。
2. 学生匹配顺序不符合使用实际：成绩表学号常为考号/格式不一，姓名通常准确；原逻辑先按学号匹配，学号对不上才按姓名。
3. **严重 bug**：成绩页 `/api/score/line` 接口疯狂请求（死循环），浏览器卡死。

## 目标与方案

### 1. 折线图请求死循环（Score.vue）
- 根因：`loadLine()` 末尾 `nextTick(renderLine)`，而 `renderLine()` 函数体就是 `loadLine()` —— loadLine → 发请求 → nextTick(loadLine) → 无限自调用。
- 修复：删除 renderLine 函数；科目下拉 `@change` 直接绑 `loadLine`；数据写入 lineData 后由既有 `watch(lineData) → drawLine` 负责重绘。

### 2. 导入匹配规则（ScoreController.findStudentId）
- 改为**先按姓名**：姓名唯一命中即用；重名时用「姓名+学号」交叉区分；姓名匹配不上再按学号兜底；都不匹配成绩仍落库（按姓名归组显示，不进在籍统计，原行为不变）。

### 3. 导入弹窗提示（Score.vue）
- 弹窗 420→520px；按钮文字缩短为「选择 Excel 文件」；下方完整说明：
  - 表头格式：学号 | 姓名 | 科目1 | 科目2 …（科目列名即科目名，可自行增减）
  - 匹配规则：先按姓名匹配，姓名匹配不上再按学号，重名以学号区分。

## 影响范围

- 后端：`ScoreController.java`（findStudentId + 注释，已重启 8088）
- 前端：`Score.vue`（弹窗、loadLine/renderLine）
- E2E：成绩步骤主动选中「E2E月考」再断言（默认选日期最新考试会撞上老师真实考试）；新增 /score/line 请求计数防死循环回归断言
