# 需求说明：双域名双库隔离与测试区免维护重置

## 一、背景与核心理念
1. **物理分库，彻底解耦**：
   - 生产域名（Prod，如 `teacher.xxx.com`）：连接正式库 `teacher_workspace`，真实教师与管理员在此工作，数据神圣不可侵犯，不参与任何重置；
   - 测试/演示域名（Dev/Demo，如 `demo.xxx.com` 或 `dev.xxx.com`）：连接独立测试库 `teacher_workspace_demo`，数据随时可能被定时重置清空；
   - 两个环境共享同一套前后端代码，由前端基于当前访问域名（或请求头）驱动后端动态切库。
2. **KISS 原则（不设防的自由体验沙箱）**：
   - 既然已经在物理数据库层彻底隔离，**无需在代码层对演示账号做任何功能或权限限制**（不拦截改密码、不限制管理员角色）；
   - 访客在测试区享有完整功能体验（包括普通教师功能、全套管理后台、个人设置等），随意折腾、修改、删除；
   - 系统全局提示：“当前为测试体验区，数据可能随时重置，仅供体验系统，请勿录入真实业务与隐私数据”；
   - 重置机制只需专注于将 `teacher_workspace_demo` 库定期/手动恢复到标准初始化数据（默认密码恢复 123456，灌入 50 人体验数据）。

---

## 二、目标与交互规范

### 1. 域名识别与切库
- **正式域名 (Prod)**：
  - 请求头透传：`X-Datasource: master`（或 Host 识别）；
  - 数据源路由至：`teacher_workspace`（正式库）；
  - 登录页：标准干净空白表单，正常输入；
  - 界面风格：正常正式环境，无任何测试横幅。
- **测试/演示域名 (Dev/Demo)**：
  - 判定条件：`window.location.hostname` 包含 `demo` 或 `dev`（本地调试支持 `localhost` 配置）；
  - 请求头透传：`X-Datasource: demo`；
  - 数据源路由至：`teacher_workspace_demo`（独立测试库）；
  - 登录页：
    - 自动预填 `admin / 123456`（具备全权限体验工作台及管理后台），用户直接点击“进入工作台 🚪”即可秒进；
    - 展示醒目卡片：“🌟 欢迎进入测试体验区，已自动填入体验账号，点击直接登录体验。本区数据可能随时重置，请勿存放真实数据”；
  - 系统内界面：
    - 全局顶部常驻柔和醒目横幅：“⚠️ **当前为测试体验区**：数据随时可能重置，仅供体验系统，请勿录入真实隐私数据！[🔄 一键恢复初始数据]”。

### 2. 测试库重置机制
- **重置目标**：仅针对 `teacher_workspace_demo` 库，物理上与正式库隔离，零风险；
- **重置周期**：每 7 天定时重置一次；同时支持在测试区界面点击“一键恢复初始数据”立即重置；
- **重置内容**：
  1. 清空 `teacher_workspace_demo` 中所有业务表数据；
  2. 保证默认管理员 `admin`（密码恢复 `123456`）；
  3. 灌入 50 名学生、周课表、男女交错座次、值日轮值、2 次考试成绩（含进退步图表）、待办事项、宠物等高保真体验数据；
  4. 恢复测试库中验证码等锁定状态。

## 三、系统架构与技术实现

### 1. 后端多数据源动态路由
采用 Spring Boot 3 官方推荐的 `dynamic-datasource-spring-boot3-starter`（或 Spring 原生 `AbstractRoutingDataSource`）：
- `application.yml` 配置：
  ```yaml
  spring:
    datasource:
      dynamic:
        primary: master
        datasource:
          master:
            url: jdbc:mysql://localhost:3306/teacher_workspace?createDatabaseIfNotExist=true&useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
            username: root
            password: root
          demo:
            url: jdbc:mysql://localhost:3306/teacher_workspace_demo?createDatabaseIfNotExist=true&useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
            username: root
            password: root
  ```
- **请求切库策略**：
  基于内置 `HeaderDsProcessor`，读取请求头 `X-Datasource`（值为 `demo` 时切到 `demo` 库，否则默认走 `master`）；
  业务层 30 个依赖 `JdbcTemplate` 的 Controller/Service 零修改！

### 2. 测试库启动与定时重置
- **启动自动建库与建表**：
  首次启动时，若 `teacher_workspace_demo` 库为空，自动执行 `schema.sql` 并执行一次演示数据灌装。
- **定时重置**：
  新增 `DemoResetScheduler`，使用 `@DS("demo")` 注解，每 7 天（或手动接口）执行清理与重置，仅作用于 demo 库。

### 3. 前端环境自适应 (`frontend`)
- **环境嗅探与请求拦截**：
  `frontend/src/api/http.js`：
  ```javascript
  const isDemo = window.location.hostname.includes('demo') || window.location.hostname.includes('dev');
  config.headers['X-Datasource'] = isDemo ? 'demo' : 'master';
  ```
- **`Login.vue`**：
  若 `isDemo` 为 true，表单默认填入 `admin / 123456`，展示测试区提示；
- **`MainLayout.vue`**：
  若 `isDemo` 为 true，在 `<main class="content">` 顶部展示测试区警告 Banner，并支持点击调用 `/api/auth/demo/reset` 恢复初始化数据。

## 四、实施计划与任务分解

1. **Task 1: 后端动态多数据源集成**
   - 引入动态数据源支持，在 `application.yml` 中配置 `master` 和 `demo` 两组数据源；
   - 验证基于请求头 `X-Datasource` 自动切库功能。
2. **Task 2: 测试库初始化与高保真数据重置服务**
   - 编写 `DemoDataService`（在 `@DS("demo")` 下运行）：负责清空 demo 库并灌装 50 人高保真体验数据；
   - 启动时自动初始化 `teacher_workspace_demo` 库；
   - 编写 `DemoResetScheduler` 7 天定时重置任务及手动重置接口 `/api/auth/demo/reset`。
3. **Task 3: 前端域名自适应与登录页改造**
   - 在 `http.js` 中自动透传 `X-Datasource` 请求头；
   - 在 `Login.vue` 中判断环境：若为测试域名自动预填 `admin / 123456` 并展示体验卡片，正式域名保持空白。
4. **Task 4: 前端测试区顶部 Banner 与一键重置**
   - 在 `MainLayout.vue` 中，若为测试域名则展示常驻醒目黄色提示横幅；
   - 支持点击“一键恢复初始数据”弹窗二次确认并刷新。
5. **Task 5: 全流程测试验证**
   - 验证正式域名下使用真实数据，数据完全写入 `teacher_workspace`；
   - 验证测试域名下使用体验数据，任意增删改均写入 `teacher_workspace_demo`；
   - 验证测试库一键重置与定时重置，确认正式库丝毫未受影响。
