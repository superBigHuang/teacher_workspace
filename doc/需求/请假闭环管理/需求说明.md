# 请假闭环管理 需求说明

## 背景与问题
- 现状：早读考勤里"请假"只是一个状态格子，家长微信请假后没有单据记录：谁请的、什么假、请到哪天、回来了没有，全靠老师记。
- 痛点：
  1. 学生请假到期没来，老师容易忘跟进（安全隐患，校方最在意）；
  2. 学期末统计病假/事假天数没有台账（病假累计超规定天数需上报、休学提醒）；
  3. 请假当天考勤要手动一格格点"请假"，重复劳动。

## 目标
1. 请假单据登记：学生、类型（病假/事假/公假）、起止日期、天数、事由、家长告知方式，形成请假台账。
2. 闭环提醒：工作台显示"请假中 X 人 / 今日应销假 X 人"，老师一键销假。
3. 考勤联动：请假期间早读考勤自动标记"请假"，销假后自动恢复。
4. 学期统计：每人累计病假/事假天数，超阈值预警。

## 非目标
- 不做家长端申请/审批流（家长通过微信/电话告知，老师代登记；KISS）。
- 不做学校层级的请假审批流程（年级主任审批等）。
- 不做请假条附件上传（v2 可选：家长微信截图留存）。

## 需求范围

### A. 请假登记（班级日常页新增"请假管理"页签，工作台卡片快捷入口）
- 登记表单：学生（下拉本班）、类型（病假/事假/公假）、开始日期、结束日期、天数（自动算=结束-开始+1，可改，支持 0.5 天/半天）、事由、家长告知方式（微信/电话/书面/口头）、备注。
- 登记后状态为「请假中」，列表按应返校日期排序置顶。
- 同一天重复登记给出提示但允许（补录场景）。

### B. 销假闭环
- 「请假中」列表每条带"销假"按钮；学生实际返校日可填（默认今天）。
- 工作台新增/复用卡片：今日请假 X 人（名单）、今日应销假 X 人（红色提醒）；点"一键销假"批量处理今日返校学生。
- 超期未销假（结束日期 < 今天 仍未销假）在列表和工作台标红「未归校」。

### C. 考勤联动
- 登记请假后，请假区间内该生的早读考勤自动置为"请假"（写入 attendance，状态请假），无需手动逐格点。
- 若老师已手动标记过该区间考勤（如迟到），保留老师标记不覆盖，仅补空白日期。
- 销假不影响已生成的请假考勤记录（台账留痕）。

### D. 学期统计与预警
- 学生档案/成长档案中显示本学期请假天数（病假 X / 事假 X / 公假 X）。
- 台账页提供按学生汇总视图；个人设置新增预警阈值"病假累计预警天数"（默认 20 天，可改），超阈值学生在列表标⚠️并提示"按校规需上报/建议休学评估"。
- 统计区间同评语/通知单：学期起止日期（term_start/term_end）。

## 数据方案
- 新表 `leave_record`：
  `id, user_id, student_id, leave_type(病假/事假/公假), start_date, end_date, days(DECIMAL(4,1)), reason, notify_method(微信/电话/书面/口头), status(ACTIVE/DONE), return_date, created_at`
  索引：`(user_id, student_id)`、`(user_id, status, end_date)`。
- 新接口（LeaveController，按 uid 隔离）：
  - `GET /leave/active`：请假中列表（含学生姓名/应返校日/是否超期）
  - `GET /leave/list?studentId=&month=`：台账（可按学生/月份过滤）
  - `POST /leave`：登记（同时联动写区间内 attendance 请假状态）
  - `POST /leave/{id}/return`：销假（return_date 默认今天）
  - `DELETE /leave/{id}`：误登记删除（同步清掉本单据自动写入的请假考勤）
  - `GET /leave/summary`：本学期汇总（工作台卡片 + 每生天数，供档案/通知单复用）
- DataInitializer 幂等建表。

## 影响范围
- 后端：新增 LeaveController；DataInitializer 建表；Dashboard stats 增 todayLeave/overdueReturn；考勤汇总读取并入请假天数。
- 前端：Daily.vue 加"请假管理"页签（登记表单+请假中列表+台账）；工作台卡片增请假/销假提醒；学生抽屉/成长档案显示请假天数；Settings 加预警阈值（+学期起止日期，与评语需求共用）。
- 数据联动：attendance 表已有"请假"状态，无需改表。

## 验收标准
- 登记一条 3 天病假后：请假中列表显示该生；班级日常早读考勤对应 3 天自动为"请假"；工作台显示"请假中 1 人"。
- 结束日期次日，工作台显示"今日应销假 1 人"；销假后状态变已销假，档案请假天数 +3。
- 结束日期过后仍不销假，列表与工作台标红"未归校"。
- 删除请假单据后，其自动写入的请假考勤一并清除（老师手动标记的不动）。
- 病假累计超阈值（默认 20 天）的学生在台账标⚠️。
- 数据隔离：A 账号登记的请假 B 账号不可见。
- E2E：API 全链路——登记→active 列表→考勤自动请假→销假→汇总天数→删除回滚。

## 待确认
1. 半天请假是否需要（0.5 天）？建议支持（中学上午/下午请假常见）。
2. 预警阈值默认 20 天是否合适（校规各异）？做成可配置即可，默认值可再定。
3. 是否需要"续假"操作（一条病假延两天）？建议 v2：本期用"删旧登新"或直接编辑结束日期兜底（登记后允许编辑结束日期）。

## 方案结论摘要
一张新表 + 一个新 Controller，闭环价值高（安全提醒是班主任刚性责任）；考勤联动是最省事的体验亮点；学期统计同时喂给成长档案与家长通知单，三个需求共用"学期区间聚合"底层，建议同期开发。

## 落地结果

### ② 请假闭环（2026-09-01 完成）
- **新表 `leave_record`**（schema.sql 幂等建表）：leave_type（病假/事假/公假）、起止日期、`days DECIMAL(4,1)` 支持 0.5 半天、事由、notify_method（微信/电话/书面/口头）、status（ACTIVE/DONE）、return_date；索引 (user_id,student_id)、(user_id,status,end_date)。
- **attendance 加 `leave_id` 列**（DataInitializer 幂等迁移）：联动考勤留痕，删单/缩短时据此精确回滚，老师手动标记 leave_id 为空不受影响。
- **后端 `LeaveController`（/api/leave，按 user_id 隔离）**：
  - `GET /active` 请假中名单：overdue（未归校）/returnToday（今日应销假）/inLeaveToday 标记，按应返校日升序；
  - `GET /list` 台账：可按 studentId、month=yyyy-MM 过滤，含已销假；
  - `POST /` 登记：区间内考勤 `INSERT IGNORE` 自动置"请假"（已有手动标记的日期跳过不覆盖）；
  - `PUT /{id}` 编辑（**续假兜底**）：改结束日期延长时新区间补写考勤，缩短时回滚多出日期的自动考勤；
  - `POST /{id}/return` 销假（return_date 默认今天，考勤历史留痕）；
  - `DELETE /{id}` 删单：按 leave_id 精确回滚自动考勤；
  - `GET /summary` 学期汇总：每生 totalDays/sickDays/personalDays/publicDays/cnt，病假≥阈值 warn=true；工作台四计数 activeCount/todayLeaveCount/todayReturnCount/overdueCount。
- **病假预警阈值** `sick_leave_warn_days` 默认 20，UserDataSeeder 对新用户与 admin 存量 INSERT IGNORE 补齐；个人设置页可改。
- **前端**：
  - Daily.vue 加"🏖️ 请假管理"页签：登记表单（天数按起止自动算、可手改 0.5）、超期红色 alert / 今日应销假黄色 alert、请假中表（未归校红标、销假/编辑/删除）、台账（月份过滤、病假超阈值 ⚠️ 标签列出学生）；
  - Dashboard.vue 加固定"请假提醒条"（奶油黄卡，不参与拖拽排序）：请假中/今日应销假/未归校三数字 + 名单标签 + **一键销假**（今日应销假+超期批量）+ 请假管理跳转。
- **验证**：API 冒烟全链路通过（0.5 天半天假、考勤联动、汇总计数、销假、删除回滚）；前端 build 通过；E2E 全量 19.0s 通过——新增断言：登记→明天考勤自动"请假"且今天手动"迟到"不被覆盖→工作台请假卡可见→续假延长后天考勤补写→销假→summary 病假天数→删单考勤回滚。
- **待确认问题结论**：① 支持 0.5 天半天 ✅；② 阈值可配置默认 20 天 ✅；③ 续假用"编辑结束日期"兜底 ✅（PUT 接口已实现，延长补考勤/缩短回滚）。
