# 评语助手与成长档案 需求说明

## 背景与问题
- 期末班主任要给全班每人写 200 字左右评语（50 人 ≈ 上万字），是学期末最大的文字工程；对着表格回忆每个学生的表现，耗时且写得千篇一律。
- 库里已沉淀一学期数据：考勤迟到/请假、作业未交、课堂纪律、成绩走势、家校沟通、班委职务——但目前只登记不汇总，写评语时仍靠老师脑子记。
- 家长会上老师要讲单个学生情况，数据散在 6 个模块里，临时翻找。

## 目标
1. **评语助手**：按学期自动汇总每个学生的结构化素材，用规则模板生成个性化评语草稿（学业/纪律/考勤/闪光点/期望），老师逐人微调后保存，期末一键打印「全班评语册」。
2. **成长档案**：学生视角的一人一页——本学期汇总数字卡 + 成绩走势 + 考勤/作业/纪律/沟通合并时间线，家长会、个别谈话、接班交接直接用。
3. 全部离线生成（规则模板，不接外部 AI），数据不出校。

## 非目标
- 不做 AI 大模型生成（预留接口位置，待确认是否后续接入）。
- 不做学生/家长自助查看端（仅老师端）。
- 不做历史学期自动归档 UI（依赖新学期升级功能，另立需求）。

## 需求范围

### A. 学期界定（前置）
- 个人设置增加「学期起止日期」（term_start / term_end，存 setting），默认 2026-09-01 ~ 2027-01-31。
- 所有"本学期"统计（评语素材、档案、通知单、请假统计）统一用该区间过滤。

### B. 评语助手（新页面 /comment，侧边栏"成绩分析"附近，名"期末评语"）
- 左：本班学生列表（带状态点：未生成/已生成/已保存）。
- 右：素材条（本学期数据）+「✨ 生成草稿」按钮 + 可编辑文本域 + 保存。
- **素材指标**（每生）：
  - 考勤：迟到次数、缺勤次数、请假天数（联动请假表）
  - 作业：未交次数、最近未交科目
  - 纪律：违纪条数
  - 学业：最近两次考试总分排名变化（↑/↓/新）、班级位次段（前 10 / 中上 / 中等 / 待努力）
  - 闪光点：班委职务、值日参与、家校沟通次数（家长配合度）
- **模板规则**（规则引擎，句式库随机+条件组合，避免雷同）：
  - 总评句 → 学业句（进步/稳定/下滑/优异四档）→ 纪律考勤句（全勤表扬/温和提醒）→ 闪光点句（班委/值日/集体活动）→ 期望句；每档 3~5 个句式随机取。
  - 示例："小茗同学本学期总成绩稳居班级前 10 名，相比开学考排名提升 3 名；坚持全勤，作业按时上交，作为学习委员认真负责。希望下学期在课堂发言上更主动一些，老师期待你更大的进步！"
- 评语长度 150~250 字，语气第二人称、鼓励为主。
- 支持手动编辑后保存；「打印评语册」：A4 排版，每生一块（姓名+评语），浏览器打印/另存 PDF。

### C. 成长档案（花名册学生抽屉新增「📈 成长档案」页签）
- 顶部数字卡：本学期迟到 X / 请假 X 天 / 作业未交 X / 违纪 X / 沟通 X 次 / 排名变化。
- 成绩走势图：各次考试总分（或均分）折线（ECharts，复用成绩页能力）。
- 时间线：按日期倒序合并该生全部记录——考勤异常、作业未交、违纪、家校沟通、请假，每条带类型 emoji 与内容。
- 抽屉内即可看完，不另开页面。

## 数据方案
- 新表 `comment`：`id, user_id, student_id, term, content, updated_at`，唯一键 `(user_id, student_id, term)`。
- 新接口（CommentController，按 uid 隔离）：
  - `GET /comment/materials`：全班素材（一次性返回，列表页用）
  - `GET /comment/material?studentId=`：单生素材（档案/生成用）
  - `POST /comment/generate`：`{studentId}` → 规则引擎返回草稿文本（不自动落库）
  - `PUT /comment/save`：`{studentId, term, content}` 保存/更新
  - `GET /comment/list?term=`：已保存评语（打印册用）
- 成长档案数据复用素材接口 + 现有成绩/记录查询，按 student_id 聚合。
- 迁移：comment 建新表（DataInitializer 幂等建表或 schema.sql）。

## 影响范围
- 后端：新增 CommentController（+模板引擎类 CommentGenerator）；setting 增 term_start/term_end 种子；个人设置 profile 接口透传两个日期。
- 前端：新增 `views/Comment.vue` + 路由/侧边栏入口；Roster 学生抽屉加"成长档案"页签；Settings.vue 加学期起止日期。
- 文档/打印：评语册打印样式（@media print）。

## 验收标准
- 评语页对 40 名学生均可一键生成草稿，内容含该生真实数据（排名变化/迟到次数等与库中一致），同班两人草稿不雷同。
- 草稿可编辑、保存、刷新后仍在；学生列表状态点正确。
- 评语册打印排版为 A4，每生一块，浏览器可直接另存 PDF。
- 学生抽屉"成长档案"数字卡与各模块明细一致；时间线含全部五类记录且按日期排序。
- 学期起止日期修改后，素材统计区间随之变化。
- E2E：生成草稿→编辑保存→刷新仍在；档案数字与花名册/日常页一致。

## 待确认（结论）
1. ~~纯规则模板还是大模型~~ → **AI 优先 + 规则模板降级**，详见《AI助手接入》需求；模板引擎照做作为 fallback。
2. 评语是否需要"班主任评语 + 学生自评 + 家长寄语"三段式？本期建议只做班主任评语。
3. 成长档案是否需要导出/打印（一人一页 PDF）？本期建议先抽屉内查看，打印随评语册一起做 v2。

## 方案结论摘要
数据全在库，核心工作量在"素材聚合 SQL + 句式模板引擎"两块，无新数据采集负担；评语落库一张新表；成长档案寄生在现有学生抽屉。离线规则生成，与项目"无 API Key"原则一致。

## 落地结果

### ① 地基（2026-09-01 完成，评语/通知单/档案/请假四需求共用）
- 学期界定：setting 新增 `term_start`/`term_end`（默认 2026-09-01~2027-01-31），UserDataSeeder 对新用户与 admin 存量均 INSERT IGNORE 补齐；`SettingsController` PUT /settings/profile 透传 termStart/termEnd；Settings.vue 个人资料卡加"学期起止日期"两个日期选择器。
- 请假表提前落地：`leave_record` 建表（schema.sql，启动自动建），含 leave_type/start_date/end_date/days(DECIMAL 4,1 支持半天)/reason/notify_method/status/return_date，索引 (user_id,student_id)、(user_id,status,end_date)。
- 学期聚合服务 `service/TermStatsService`：批量查询内存聚合（无 N+1），每生输出 late/absent/leaveDays/sickLeaveDays/homeworkMissing/lastMissingSubject/discipline/commCount/roles/dutyCount，以及最近两次考试 total/rank/rankChange（正数=上升）/rankSegment（前10/中上/中等/待努力）；学期区间统一取 term_start~term_end。
- 接口 `TermController`：`GET /api/term/materials`（全班，附 termStart/termEnd）、`GET /api/term/material?studentId=`（单生）。
- 验证：前端 build 通过；E2E 全量 19.8s 通过（新增学期日期保存、materials 40 人结构字段断言、单生接口断言）。

### ⑤ 评语助手 + 成长档案（2026-09-01 完成）

**后端**：
- `comment` 新表（schema.sql 幂等）：id/user_id/student_id/term（term_start~term_end 拼接）/content/source(ai/template/manual)/updated_at，唯一键 (user_id, student_id, term)。
- `CommentController`（/api/comment，按 uid 隔离）：
  - `GET /materials`：全班素材（复用 TermStatsService）+ 本学期已保存评语映射（状态点用）；
  - `GET /material?studentId=`：单生素材 + 已保存评语；
  - `POST /generate`：调 AiService scene=comment（AI 优先、失败自动降级规则模板，不落库）；
  - `PUT /save`：upsert 评语（唯一键，重复保存走 UPDATE）；`DELETE /{studentId}`：删除本学期评语；
  - `GET /list`：已保存评语 + 抬头（学校/班级/班主任，评语册打印用）；
  - `GET /archive?studentId=`：成长档案聚合包（material 数字卡 + trend 成绩走势 + timeline 时间线）。
- `TermStatsService` 新增两个方法：`examTrend`（学期内全部考试该生总分/名次，缺考不出点）、`timeline`（合并考勤异常/请假单/作业未交/纪律/沟通五类记录，统一 {date,type,emoji,text} 按日期倒序；考勤"请假"行与请假单重复故不取）。

**前端**：
- 新增 `views/Comment.vue` + 侧边栏"📝 期末评语"入口（成绩分析旁）：左侧学生名单带三色状态点（绿=已保存/黄=已生成草稿/灰=未生成）+ 搜索；右侧素材条（学业/考勤/作业/纪律/闪光点五栏）+ ✨生成草稿 + 可编辑文本域 + 保存/删除；顶部"✨ 批量生成草稿"（3 worker 并发，进度条 + "约需 2 分钟"文案，仅对未保存学生生成）与"📖 打印评语册"。
- 新增独立路由 `/print/comments` + `views/CommentBook.vue`：A4 评语册（抬头 + 每生一块姓名+评语，块内 `page-break-inside: avoid` 不跨页断开），数据经 sessionStorage 传新窗口。
- `Roster.vue` 学生抽屉改为 el-tabs 双页签："📇 基本档案"（原内容）+ "📈 成长档案"（6 张数字卡：迟到/请假天/作业未交/违纪/沟通/排名变化↑绿↓红；ECharts 成绩走势双轴折线——总分+排名逆序副轴；五类记录时间线 emoji 列表），切到档案页签才加载。

**验证**：`npm run build` 通过；E2E 全量 25.5s 1 passed——新增 11c（materials 40+人字段断言、UI 单人生成草稿文本>50 字、API 生成→编辑保存→再查仍在→评语册含该生→删除、打印页路由可打开）与 11d（archive 结构断言、时间线含考勤迟到、真实学生走势含学期内考试、抽屉档案页签数字卡 + canvas 走势图渲染）；写操作均针对临时测试生并在 afterAll 兜底清理，不污染 40 名真实学生。

**与原设计的偏差（备忘）**：
- 评语生成由"纯规则模板"升级为 AI 优先（讯飞星火）+ 规则模板降级（待确认 1 结论，详见《AI助手接入》）；星火共享 key 已内置 yml 开箱即用，真实链路已实测通过（评语约 24s/人、200 字干净正文）；E2E 回归时临时关闭 AI 走模板以保证速度与稳定。
- 评语 source 记录来源（ai/template/manual），评语册 AI 生成条目标 ✨。
- 成长档案暂不支持导出/打印（待确认 3 结论：抽屉内查看，打印随 v2）。
- 评语只做班主任评语（待确认 2 结论）。
