# 账号体系与可爱化改造 需求说明

## 背景与问题
当前系统为单账号（写死 admin/123456）、单密码进入；无注册、无个人设置；学校/班级/学科不可配置；UI 为素粉彩，不够可爱。

## 目标
1. 注册功能：账号、密码、确认密码、邀请码（邀请码暂不强制校验，仅留输入框）。
2. 账号密码登录（替代单密码进入）。
3. 个人设置菜单：改密码、配置邮箱、配置学校、配置班级与学科。
4. 学校选择：输入框 + 全校共享自动补全记忆（输入"嘉善第四中学"入库，任何人输入"嘉善"可下拉选到）。
5. 多老师账号数据互相独立（各账号只看自己的班级/学生/成绩/值日等）。
6. UI 换为「奶油糖果马卡龙」风格：大圆角、糖果色、奶油投影、贴纸 emoji、圆润字体。

## 非目标
- 不做地区级联、不接地图 API、不内置全国学校库（用户拍板：学校用输入框+记忆）。
- 邀请码不做真实校验/审批体系。
- 不做角色权限（无管理员/普通区分）。

## 方案结论
### 后端
- `sys_user` 增列：email、school；username 作为登录账号（唯一）。
- 所有业务表加 `user_id BIGINT`；查询/写入按当前登录 uid 过滤。
- 全局共享模板表不加 user_id：`period`（节次时间）、`quick_note_rule`（速记关键词）、`school_dict`（学校记忆，全校共享）。
- 唯一约束调整（多用户共存）：student(user_id,stu_no)、duty_config(user_id,day_of_week)、card_config(user_id,card_key)、setting 主键改 (user_id,k)。
- 新用户注册后初始化自己的默认数据：默认班级、科目、值日事项/人数、节假日、卡片顺序、默认设置（无学生）。
- 接口：`POST /auth/register`、`POST /auth/login`(账号+密码)、`GET /auth/me`、`POST /auth/change-password`；`GET/PUT /settings/profile`；`GET /schools?q=`（学校记忆）。
- 迁移幂等：DataInitializer 用 JDBC 元数据判断列/索引再 ALTER；现有业务数据 user_id 置 1（admin）。

### 前端
- Login 页改「登录 / 注册」双 Tab：登录=账号+密码；注册=账号+密码+确认密码+邀请码。
- 新增 `Settings.vue`（路由 /settings）：账号信息（显示名/邮箱）、学校（el-autocomplete 远程记忆）、班级管理、学科管理、修改密码。
- 侧边栏底部加用户区：名字 + ⚙️个人设置 + 退出登录。
- theme.css 换奶油糖果马卡龙：暖奶油底、糖果渐变、圆角 18~24px、柔和奶油投影。

## 影响范围
- 后端：AuthController、WebConfig、DataInitializer、schema.sql、全部业务 Controller（加 uid 过滤）。
- 前端：Login.vue、MainLayout.vue、router、theme.css、新增 Settings.vue。

## 验收标准
- 可注册新账号（邀请码任意填）；注册后进入自己的空工作台。
- 用账号+密码登录；错误有提示；刷新保活。
- 新账号看不到 admin 的 40 名学生；admin 登录数据仍在。
- 个人设置可改密码、邮箱、学校；学校输入"嘉善"能下拉出"嘉善第四中学"（跨账号可见）。
- 班级、学科可在设置页增删改。
- 整体 UI 为奶油糖果马卡龙风格，圆角/配色/投影统一。
- Playwright 全站回归通过（含注册→登录→设置新流程）。

## 落地结果（2026-09-01 完成）
- 后端 10 个 Controller 全部按 uid 隔离（BaseController.uid() 取 JWT 中 uid）；迁移幂等，重启自动完成，admin 存量 40 名学生数据完好。
- 新账号注册即得空脚手架（2 班级/11 科目/5 值日事项/节假日/卡片/默认设置），花名册为空。
- 前端：Login 双 Tab（登录/注册，飘浮糖果背景）、Settings 四卡（资料/改密/班级/学科）、侧边栏底部用户区（🐻 头像+姓名+学校+设置+退出）、theme.css 奶油糖果马卡龙全站换肤。
- E2E 全绿（26.9s）：新增覆盖——注册 Tab 四字段、注册新账号→花名册 0 人/admin 40 人隔离、学校记忆跨账号搜索（"E2E糖果中学" admin 可见）、改密码后新密码可登录旧密码被拒、设置页 4 卡可见；原有 8 模块走查全部保持通过。
- 测试残留账号（可选清理，SQL 交用户执行）：`DELETE FROM sys_user WHERE username IN ('smoke_teacher','e2e_teacher');`（其脚手架行无 uid 引用，不会在任何账号下显示）。
