# AI 助手接入（LLM 可配置 + 评语/通知单智能生成）需求说明

## 背景与问题
- 评语助手与家长成绩通知单两个需求都需要"文字生成"环节：期末评语（150~250 字/人）、通知单教师寄语（30~80 字/人）。
- 纯规则模板生成稳定离线但句式八股；接入大模型可生成个性化、自然的文字，质量质变。
- 各老师条件不同：有人有自己的 DeepSeek/通义/OpenAI key，有人没有。需要"系统提供默认服务 + 用户可自配覆盖"，且**没配/调用失败时自动降级到规则模板**，功能永不不可用。

## 目标
1. 统一的 AI 接入层：OpenAI Chat Completions 兼容协议（市面主流服务与本地 Ollama 均兼容）。
2. 配置两级：部署者预置默认 LLM（application.yml，用户提供）；老师可在个人设置自配 base URL / API Key / 模型 / 参数覆盖默认。
3. AI 能力落地两个场景：**期末评语生成**、**通知单教师寄语生成**；均带规则模板降级。
4. 设置页提供"测试连接"，配置错误当场可见。

## 非目标
- 不做 AI 通用聊天机器人（本期只两个场景，接口预留 scene 扩展）。
- 不做流式输出（评语短文本，一次性返回；批量走并发+进度条）。
- 不做前端直连 LLM（key 会泄露且有 CORS 问题，一律后端代理）。
- 不做 token 用量计费/统计（v2 可选）。

## 总体架构

```
前端（Settings/评语页/通知单弹窗）
   │  /api/ai/*（带 JWT）
   ▼
后端 AiController → AiService（配置解析：用户覆盖 > 全局默认 > 未启用）
   │  RestClient（超时/重试1次）
   ▼
LLM 服务商（OpenAI 兼容 /chat/completions）
   │  失败/超时/未配置
   ▼
规则模板引擎（CommentGenerator，保底，永不失败）
```

- 后端用 Spring 内置 `RestClient`（Spring Boot 3.3 自带，无需新依赖）调 `/v1/chat/completions`。
- 生成接口统一返回 `{ content, source: "ai" | "template", model? , error? }`，前端标注来源。

## 配置项设计

### 两级配置
| 层级 | 位置 | 说明 |
|---|---|---|
| 全局默认 | `application.yml`：`ai.defaults.base-url / api-key / model / temperature / timeout-ms` | 部署者预置（用户提供默认服务）；对前端不可见明文 |
| 用户覆盖 | setting 表键：`ai_enabled / ai_base_url / ai_api_key / ai_model / ai_temperature` | 老师在个人设置自配；留空的字段回退默认值 |

**生效逻辑**：`ai_enabled=false` → 直接用模板；`true` 时逐字段取值（用户值优先，空则默认值）；apiKey 最终为空 → 降级模板。

### 配置字段
| 字段 | 默认值 | 说明 |
|---|---|---|
| base URL | 部署者提供 | OpenAI 兼容地址，如 `https://api.deepseek.com`（不带 /v1 也容错，后端自动补） |
| API Key | 部署者提供 | 仅存不明取：GET 接口返回 `hasKey:true/false` 与掩码 `sk••••1234` |
| 模型名 | 部署者提供 | 如 `deepseek-chat`、`qwen-plus`、`gpt-4o-mini` |
| temperature | 0.7 | 评语略高(0.8)、寄语 0.6，后端按场景给默认，用户可改 |
| 超时 | 60 秒 | 推理模型单条约 10s；超时即降级，不阻塞页面 |
| max_tokens | 按场景 | 评语 3000 / 寄语 1500 / 测试 50（推理模型思考过程共享配额，必须给足） |

## 数据方案
- 无新表：用户配置存 `setting`（user_id+k 复合主键，已支持）。
- `application.yml` 增配置段（key 也支持环境变量 `AI_API_KEY` 覆盖，避免入库 git）：
  ```yaml
  ai:
    defaults:
      base-url: ${AI_BASE_URL:https://maas-api.cn-huabei-1.xf-yun.com/v2}
      api-key: ${AI_API_KEY:}        # 星火 key 部署时注入环境变量，不入库 git
      model: ${AI_MODEL:spark-x2.5-4b}
      temperature: 0.7
      timeout-ms: 60000
  ```

## 后端接口（AiController，`/api/ai`，按 uid 隔离用户配置）
| 接口 | 说明 |
|---|---|
| `GET /ai/config` | 返回当前生效配置：`{enabled, baseUrl, model, temperature, hasDefaultKey, hasUserKey, keyHint}`（**绝不明文返回 key**） |
| `PUT /ai/config` | 保存用户配置 `{enabled, baseUrl, apiKey(空串=不修改, "__clear__"=清除), model, temperature}` |
| `POST /ai/test` | 用当前生效配置发一条 "ping" 短请求，返回 `{ok, message, model}`，错误信息含 HTTP 状态与服务商返回摘要 |
| `POST /ai/generate` | 统一生成：`{scene:"comment"|"message", studentId, examId?, compareExamId?}` → `{content, source, model?}`；AI 失败自动降级模板，`source` 标明来源，`error` 带降级原因 |

- 评语/通知单原计划的 `/comment/generate`、报告数据包接口改为内部调 AiService；模板引擎保留为 AiService 的 fallback 组件。
- 批量评语：前端循环调 `/ai/generate`（并发 3），逐人回填+进度条；单条失败不影响其他人（该人落模板）。

## Prompt 设计（后端模板，素材以 JSON 注入）

### scene=comment（期末评语，150~250 字）
- System（定稿，已实测）：
```
你是一位经验丰富的中学班主任，正在为学生写期末评语。要求：
1) 用第二人称"你"称呼学生，语气真诚温暖、鼓励为主，符合班主任口吻；
2) 评语正文 150~250 字；
3) 必须自然引用素材中的具体事实（班级排名、排名变化、迟到次数、作业情况、职务、家校沟通等），数据要准确，不许编造素材中没有的事实，不许空泛套话；
4) 结构：先肯定优点与进步，再委婉指出需要改进之处，最后表达期望与鼓励；
5) 素材中表现不佳的数据（如迟到、未交作业）要点到但措辞温和，不贴标签；
6) 直接输出评语正文，不要输出思考过程、字数统计、标题、序号或任何说明。
```
- User：`请根据以下学生本学期素材写期末评语：${素材JSON}`
  素材字段：姓名、学期、班级、学业{班级排名,排名变化,位次段,总分均分对照}、考勤{迟到,缺勤,请假天数}、作业{未交次数}、纪律{违纪条数}、闪光点{职务,值日参与,家校沟通次数}
- 参数：temperature 0.8，max_tokens 3000，超时 60s。
- 实测：255 字输出，排名/进步名次/迟到次数/职务/沟通次数全部正确，10.3s。

### scene=message（通知单寄语，30~80 字）
- System（定稿）：
```
你是一位中学班主任，要在学生的成绩通知单"教师寄语"栏写一段话，学生和家长都会看到。要求：
1) 30~80 字，简短温暖；
2) 结合素材中的成绩进退步与在校表现，进步的给予肯定、退步的委婉鼓励，不批评指责；
3) 可以对家长提一句配合建议（如"请家长多关注作业完成情况"）；
4) 直接输出寄语正文，不要思考过程、标题或说明。
```
- User：`请写教师寄语：${JSON}`，字段：姓名、考试名、总分、班级排名、排名变化、日常表现{迟到,作业未交,违纪,请假天数}
- 参数：temperature 0.6，max_tokens 1500。

### scene=ping（测试连接）
- User：`回复"连接正常"四个字即可。` max_tokens 50。

### 降级兜底链
content 非空 → 直接用；为空但 reasoning_content 非空 → 提取"最终输出/评语：/寄语："之后文本；仍无 → 规则模板。返回 source 标注 ai / template。

## 前端交互
1. **个人设置新增「🤖 AI 助手」卡**（马卡龙紫）：启用开关、base URL、API Key（密码框，占位显示"已配置，留空不修改"）、模型名、temperature 滑块、「测试连接」按钮（✅ 连通显示模型名 / ❌ 显示错误原因）、隐私提示文案。
2. **评语页**：「✨ AI 生成」按钮（未启用 AI 时显示为「生成草稿」走模板）；生成后文本域上方标注 `✨ AI 生成 · deepseek-chat` 或 `📝 模板生成（AI 不可用）`；批量按钮带进度条（已生成 23/40）。
3. **通知单弹窗**：寄语选项增「AI 逐人生成寄语」勾选；生成报告时并发调用，失败的人用统一寄语兜底。
4. 降级对用户透明：任何 AI 错误只在来源标签里体现，不弹阻断性错误。

## 隐私与安全
- 设置卡固定提示："学生姓名与在校表现数据将发送至你配置的 AI 服务商，请使用合规服务；使用系统默认服务则数据发往管理员预置的服务。"
- API Key 存储：用户 key 存 MySQL setting 表（本地服务器）；GET 接口永不返回明文；yml/环境变量中的默认 key 不下发浏览器。
- 后端日志不记录 key 与完整 prompt 内容（只记 scene、耗时、成功/失败）。

## 影响范围
- 后端：新增 `AiController`、`AiService`（配置解析+RestClient 调用+降级）、`CommentGenerator`（模板引擎，fallback）；`application.yml` 加 ai 段；评语/通知单接口接入 AiService。
- 前端：Settings.vue 加 AI 卡；Comment.vue（评语页）AI 生成与批量进度；通知单弹窗加 AI 寄语选项。
- 依赖：无新增（RestClient 为 Spring 内置；Jackson 已有）。

## 验收标准
- 未配置任何 AI 时：评语/寄语生成走模板，功能正常，来源标注"模板"。
- 配置错误的 base URL/key：测试连接返回明确错误；生成评语时自动降级模板，不报错阻断。
- 配置正确（默认服务或自配）：评语内容含该生真实数据（排名/迟到等与库中一致）、语气自然、两人不雷同；寄语 80 字内。
- 批量生成 40 人：并发执行有进度，全部回填；其中模拟 1 人失败时该人落模板、其余正常。
- 刷新页面后配置仍在；GET 接口抓包看不到 key 明文；清除 key 后回退默认服务。
- E2E：测试连接接口（默认服务可用时）通；评语生成接口返回 content 非空且 source 为 ai/template 之一；未启用时 source=template。

### ⚠️ 推理模型适配要点（spark-x2.5-4b 为 reasoning 模型，实测踩坑）
1. 响应中思考过程在 `message.reasoning_content`，正式正文在 `message.content`；**token 配额被思考过程共享**。
2. **max_tokens 必须给足**：1000 时思考吃光配额、content 为空（finish_reason=length）。定参：评语 **3000**、寄语 **1500**、测试连接 **50**。
3. 单条耗时约 10s：HTTP 超时设 **60 秒**；批量 40 人并发 3 ≈ **2~3 分钟**，进度条必需（文案"AI 正在为每位同学写评语，约需 2 分钟"）。
4. 兜底：content 为空但 reasoning_content 非空时，提取思考中"最终输出/评语："之后的文本；提取不到则降级模板。
5. System prompt 明确"直接输出正文，不要输出思考过程、字数统计或说明"，可显著压缩推理 token（实测 817 → 仍占大头但稳定够用）。
6. 后端字段映射兼容标准 OpenAI 响应即可（reasoning_content 为厂商扩展字段，缺失时忽略——用户自配非推理模型不受影响）。

## 方案结论摘要

## 落地结果

### ③ AI 接入层（2026-09-01 完成）
- **配置**：`application.yml` 新增 `ai.defaults`（base-url 默认星火 v2 端点、model=spark-x2.5-4b、temperature 0.7、timeout-ms 60000），api-key 走 `${AI_API_KEY:}` 环境变量注入，不入库 git。
- **`service/AiService`**（RestClient，零新依赖）：
  - 两级配置解析：setting 表 `ai_enabled/ai_base_url/ai_api_key/ai_model/ai_temperature` 用户值优先，空则回退 yml 默认；`enabled` 默认 true（默认服务开箱即用），最终 apiKey/baseUrl/model 任一为空即降级模板；
  - `chat()`：POST `{baseUrl}/chat/completions`（baseUrl 不以 /vN 结尾自动补 /v1），请求头 `Authorization: Bearer` + `lora_id: 0`；body 带 model/messages/temperature/max_tokens；连接超时 10s、读超时 60s；
  - 推理模型兜底链：`choices[0].message.content` 非空直接用 → 空则从 `reasoning_content` 提取"最终输出/评语：/寄语：/正文："之后文本 → 仍无落模板；
  - max_tokens 按场景：评语 3000 / 寄语 1500 / ping 50；温度用户未配时按场景 0.8 / 0.6；
  - 素材以中文字段名 JSON 注入 prompt（学业/考勤/作业/纪律/闪光点五段），数据全部来自 TermStatsService 学期聚合；
  - 日志只记 scene/studentId/耗时/成败，不记 key 与 prompt 内容。
- **`service/CommentGenerator`**（规则模板 fallback）：评语按"总评→学业（前10/进步/波动/稳定四档）→考勤纪律（全勤表扬或温和提醒）→作业→闪光点（职务/值日/家校配合）→期望"组装，每档句式库随机取句，只引用素材真实数据；寄语按进退步分档 30~80 字并附家长配合建议。
- **`controller/AiController`（/api/ai）**：
  - `GET /config`：返回 enabled/baseUrl/model/temperature/hasDefaultKey/hasUserKey/keyHint（用户 key 仅后 4 位掩码 `••••1234`，默认 key 不下发任何片段）；
  - `PUT /config`：baseUrl/model/temperature 留空=清除覆盖回退默认；apiKey 空串=不修改、`__clear__`=清除；
  - `POST /test`：ping 短请求返回 {ok, message, model}；
  - `POST /generate`：{scene: comment|message, studentId} → {content, source:"ai"|"template", model?, error?}，任何 AI 异常自动落模板。
- **前端**：Settings.vue 新增第五张"🤖 AI 助手"卡（马卡龙紫）：启用开关、服务地址、Key 密码框（占位提示已配置掩码/默认服务状态）、模型名、温度滑块、保存 + 🔌测试连接（结果 alert 显示模型名或错误摘要）、隐私提示文案。
- **验证**：前端 build 通过；E2E 全量 19.7s 通过——新增断言：设置页 5 张卡含 AI 助手、GET /ai/config 字段齐全且响应无 apiKey 明文、关闭 AI 后评语/寄语 source=template 且内容含学生真实姓名（评语 168 字/寄语 45 字实测）、测试连接接口结构正常。

### ③-补 共享 key 内置 + 真实星火链路实测（2026-09-01 完成）
- **key 内置**：讯飞星火为平台共享服务，key 直接写入 `application.yml`（`api-key: ${AI_API_KEY:ak-2cd4...982d}`，随 git 入库开箱即用；环境变量 `AI_API_KEY` 仍可覆盖，换 key 无需改代码）。base-url/model 同为共享默认值。

- **实测发现并修复 3 个问题**：
