# 登录安全加强 · 需求说明

> 在「登录验证码」基础上，针对一次绕过/暴破审计的结论做加固。基线文档。

## 一、背景：审计两个问题

1. **能否绕过登录进入系统？** 正常路径绕不过（后端 `/api/**` 全量 JWT 拦截，仅放行 login/captcha/带票 SSE/OPTIONS；前端 `/m`、`/radish` 免登页不触达受保护数据）。但发现两个真实口子。
2. **是否需要继续防暴力破解？** 原验证码可被 OCR + 无限取码绕过，无任何速率限制，需要加强。

## 二、审计发现的口子

| 风险 | 等级 | 说明 |
|---|---|---|
| JWT 密钥硬编码并入库 git | 高 | `application.yml` 写死密钥，知道者可离线伪造任意账号（含 admin uid=1）token，直接过拦截器，改密码也无效（JWT 无服务端失效） |
| 失败计数可被伪造 XFF 绕过 | 中 | 原 IP 取 `X-Forwarded-For` 首段，客户端每请求换一个头即可让计数永不达阈值 |
| 登录失败文案区分账号 | 低 | 「账号不存在」/「密码错误」可被用来枚举有效账号 |
| 无速率限制，验证码可 OCR | 中 | 脚本可持续撞库 |

低风险备注：`/uploads/**` 图片静态映射无鉴权（只能按文件名读、不能列目录）；`application.yml` 另硬编码了一个 AI `sk-` key（建议另行轮换，不在本次代码范围）。

## 三、已确认决策与落地（2026-09-09）

1. **JWT 密钥外置 + 换发**：`app.jwt.secret` 改为 `${APP_JWT_SECRET:dev-insecure-...}`，默认值换新（旧 token 全失效）；有效期 72h→24h（`APP_JWT_EXPIRE_HOURS` 可调）。`JwtUtil` 启动时检测到开发默认密钥会打 WARN。
2. **XFF 信任开关**：新增 `app.trust-proxy`（`TRUST_PROXY`，默认 false）。
   - false（直连）：一律用 TCP 远端地址，忽略代理头 → 伪造 XFF 失效。
   - true（在可信 Nginx 之后）：取 `X-Forwarded-For` **末段**（Nginx 追加的直连地址），防客户端伪造首段；并读 `X-Real-IP`。
3. **统一失败文案**：账号不存在与密码错误都返回「账号或密码错误」，不泄露账号是否存在。
4. **失败锁定**：`CaptchaService` 在「3 次出验证码」之上加「**同一 账号+IP，30 分钟窗口内失败 5 次锁定 10 分钟**」；锁定期即使密码正确也拒绝（不查库），成功登录清零，按 IP 维度互不连带。

**登录处理顺序**（`AuthController.login`）：先判锁定 → 再判验证码 → 最后查库校验密码；失败响应 data 按需带 `needCaptcha / locked / remainSec`，前端复用现有验证码行与错误提示，本轮前端无改动。

## 四、影响范围

- 后端：`application.yml`、`JwtUtil`、`AuthController`、`CaptchaService`。
- 行为变化：**所有现存 token 因换密钥失效，老师需重新登录一次**；连续 5 次输错会锁 10 分钟。
- 前端、数据库结构：无改动。

## 五、验证结论（2026-09-09，本地 8088）

- 后端 JDK17 编译 EXIT=0、重启正常（8089 未动）。
- API 冒烟：连错第 3 次起 `needCaptcha=true`；伪造不同 XFF 头不再拆分计数（trust-proxy=false 时第 3 次照样要验证码）；不存在账号返回「账号或密码错误」；admin 正常登录；旧/伪造 token 调 `/auth/me` 返回 HTTP 401。
- 状态机单测（临时 JUnit，验后已删）：2 次无码 / 3 次要码未锁 / 5 次锁定约 10 分钟 / 换 IP 不连带 / 验证码一次性 / 成功清零，全部通过。
- 锁定分支说明：第 4、5 次失败需带正确验证码才计数（无码请求不查库不计数），故通过服务层单测确定性验证，OCR 路径不影响该结论。

## 六、部署必做（124 服务器，重要）

代码默认是**开发密钥**，线上必须显式注入环境变量，否则启动日志有安全告警、密钥仍等同于公开：

```powershell
# 生成随机密钥（≥32 字节），任选其一：
# PowerShell:
-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 48 | ForEach-Object {[char]$_})
# 或 openssl rand -base64 48
```

- 设置系统环境变量 `APP_JWT_SECRET=<随机长串>`（写进启动脚本/计划任务环境），重启后端。
- 若服务在 Nginx 等反代之后：`TRUST_PROXY=true`，并确保 Nginx 设置 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`；**直连暴露则保持 false**。
- 可选：`APP_JWT_EXPIRE_HOURS` 调整 token 有效期。
- 部署后老师需重新登录一次（旧 token 已失效）。

## 七、非目标（本期不做）

- 不引 Redis/分布式限流（内存态，重启计数清零，单机内网足够）；不做全站 IP 限流桶、登录成功日志告警、滑块行为验证。
- 不改前端 UI（锁定/验证码提示复用现有错误条与验证码行）；不改其他敏感操作的鉴权。
