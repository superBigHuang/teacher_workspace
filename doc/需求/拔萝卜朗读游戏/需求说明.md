# 拔萝卜朗读小游戏 —— 需求分析（纯分析，未改代码）

> 2026-09-04。状态：**方案已出，待确认后出开工任务书**。
> 一句话：老师为了激励小朋友大声读书——**学生读得越响，兔子拔萝卜拔得越快**；拔出一根放胜利短片并播报"第 N 根萝卜"，早读结束放感谢短片并播报总战绩。
> 素材目录 `vedio/拔萝卜/`：`用力拔萝卜初始成片.mp4`（5.4MB，节奏控制循环源）/ `拔出萝卜成片.mp4`（7.1MB，单根胜利）/ `感谢成片.mp4`（6.0MB，结尾）。

## 核心结论（先看这个）

1. **1~3 秒拔萝卜片段：用「循环」，不用慢放。** 循环播放 [1s, 3s] 区间，用 `playbackRate` 随音量调速（0.5~2.0 倍）；慢放会把兔子动作拉成幻灯片且必然播完没有回头路，音量驱动感弱。**进度不绑视频时长，另设一根"萝卜进度条"按音量积分**，攒满才算拔出——这样"声音小就拔不动、声音大就拔得快"的因果才成立。
2. **音量模块**：Web Audio API（getUserMedia + AnalyserNode），RMS 平滑后驱动仪表盘；视频上方放一根大字音量条 + 兔兔表情反馈。
3. **三段视频状态机**：`用力拔萝卜（循环）→ 拔出萝卜（播一次 + 特效）→ 回循环 → …→ 感谢成片（结尾 + 总数）`。
4. **形态**：纯前端单页大屏路由 `/radish`，**零后端、零数据库**（v1）；接宠物系统加成长值是 v2 可选联动。
5. **课堂约束**：浏览器麦克风需 HTTPS 或 localhost + 一次用户点击授权；教室大屏电脑需确认有麦克风（无麦可用 USB 麦/领夹麦）。

## 一、背景与目标

- 早读课常见痛点：学生开口率随时间衰减，声音越来越小，老师喊破嗓子。
- 游戏化思路：**把"全班朗读音量"实时映射成一个可视、热闹、有累积感的动作**（兔子拔萝卜），声音=生产力。
- 目标：①全程开口率提升 ②有节奏起伏（不能一直吼）③每拔出一根有正反馈 ④结束有"战报"仪式感。
- 非目标：不做语音识别（不判断读得对不对，只管"响"）、不做学生个体区分（v1 是全班合力的集体游戏）、不做历史记录。

## 三、核心机制：音量 → 拔萝卜

### 3.1 音量采集（Web Audio API）

```
getUserMedia({audio:true}) → AudioContext → MediaStreamSource
  → AnalyserNode(fftSize=2048) → 每帧 getByteTimeDomainData → RMS
  → 归一化 0~1 → 指数平滑(smooth = 0.15*new + 0.85*old) → volume
```

- **环境噪声基线**：开始前 2 秒测一次环境底噪 `noiseFloor`，有效音量 = max(0, volume - noiseFloor)。教室空调/风扇底噪约 0.05~0.15，不减基线会导致兔子自己动。
- **防吹麦/拍桌**：RMS 短时尖峰（<100ms 的脉冲）限幅——拍桌子不算朗读，用 300ms 滑动窗口均值。
- 无需语音识别，不管内容只管响度，隐私上也不录存任何音频。

### 3.2 音量 → 拔萝卜进度（核心因果）

每根萝卜有**进度值 0~100**：

```
每帧(60fps)：progress += max(0, volume - 阈值) * 速度系数 * dt
```

- 阈值默认 0.15（轻声读不动，得真开口）；速度系数使**全班正常朗读音量约 15~20 秒拔一根**（早读 20 分钟 ≈ 拔 5~8 根，节奏合适）。
- 视频只是**进度的可视化**：`video.playbackRate = 0.5 + progress增速映射到 0.5~2.0`，且 video.currentTime 与 progress 同步（progress 0%→区间 1.0s，100%→区间 3.0s）。
- **关键：声音停了进度缓慢回退**（每帧 -0.3%），兔子会"滑回去"一点——制造紧张感，防止学生读一波就歇。回退不超过当前 30% 下限（保护积极性，不拔已拔出的）。

### 3.3 循环 vs 慢放（回答用户问题 3）

| 方案 | 问题 | 结论 |
|---|---|---|
| 循环 1~3s | 接缝可能轻微跳帧 | ✅ **采用**：区间内来回循环（`timeupdate` 到 3s 就 seek 回 1s），配合 playbackRate 调速，动作节奏感强、音量驱动即时可见 |
| 慢放整段 | 播完就没了；慢放时动作像幻灯片；无法响应"声音变小要变慢"的双向需求 | ❌ 不采用 |
| 正放倒放（1→3→1） | 动作最顺无接缝 | 备选：若硬切接缝明显，改用 ping-pong 播放（正向到 3s 再 playbackRate 取负不原生支持，用 currentTime 手动倒放 10fps 足够） |

## 四、画面与状态机

### 4.1 页面布局（大屏 16:9 满屏）

```
┌────────────────────────────────────────────────┐
│  🔊 音量  ▓▓▓▓▓▓▓░░░ 大声读！兔兔在用力！  [🎤已开] │  ← 顶部音量模块（大字、全班可见）
├────────────────────────────────────────────────┤
│                                                │
│            [  视频区：兔子拔萝卜  ]              │
│         （左上角叠加：萝卜进度条 ▓▓▓░ 67%）       │
│                                                │
│   🥕×3                                        │  ← 左下角已拔计数（每根一个小萝卜图标排排站）
└────────────────────────────────────────────────┘
```

### 4.2 状态机

```
IDLE（封面：兔子招手 + "点击开始"大按钮，点这里同时完成麦克风授权）
  → READY（测底噪 2s，"嘘…兔兔在听环境声音"）
  → PULLING（循环播放 1~3s，进度条随音量涨）
      progress>=100 → SUCCESS
  → SUCCESS（切"拔出萝卜成片"播一次，全屏特效"第 N 根萝卜！"+ 撒花 + 音效）
      播完 → PULLING（下一根，进度归零，速度系数可逐根 +10% 越来越难）
  → 老师点"结束早读"（或倒计时到点）→ ENDING
  → ENDING（播"感谢成片"，叠加战报：共拔出 N 根萝卜、今日最响时刻、鼓励语）
      播完 → IDLE（显示"明天继续加油"）
```

### 4.3 音量模块设计（视频上方）

- **主音量条**：横向大进度条，高度 40px+，颜色三段（绿→黄→红，红=足够响），全班最后一排也能看清。
- **实时数值**：当前音量百分比 + 兔兔表情联动（😴 没声 / 🙂 小声 / 😆 够响）。
- **引导语轮换**："大声读！兔兔在用力！""就差一点！""保持住！🔥"。
- 右侧小字显示麦克风状态（已开/被禁用→红色引导重新授权）。

## 八、技术落地要点

- **新路由**：`/radish`，**独立全屏页**（同 /login 级别，不进 MainLayout，不显示侧边栏），投屏专用。
- **零后端**：v1 不建表、不加接口；素材放 `frontend/public/radish/`；纪录存 localStorage。
- **麦克风权限**：浏览器要求安全上下文（HTTPS 或 localhost）。老师已确认**线上部署、有域名有 HTTP**——**必须给域名配 HTTPS 证书才能用麦克风**（Let's Encrypt 免费证书 + nginx ssl，见第十一节）；这是开工前置条件。
- **授权时机**：IDLE 页"点击开始"按钮的 click 回调里调 getUserMedia（浏览器要求用户手势）。
- **大屏性能**：视频 `playsinline muted=false`（视频原声可用）+ 音量条/特效全走 transform/opacity；60fps 用 requestAnimationFrame 驱动进度。
- **灵敏度设置**：右上角齿轮（平时隐藏，鼠标移入显示）：音量阈值滑块、每根目标秒数、倒计时分钟数、测试麦克风按钮。
- **意外恢复**：页面刷新回到 IDLE（游戏状态本就不该恢复，KISS）。

## 十二·补、v1.1 修复（2026-09-07）：静音时视频"一抽一抽"

- **现象**：localhost 实测，没声音时兔子画面在极小范围内反复跳（"重复没几帧、一抽一抽"）；有声音时正常。
- **根因**：`pullLoop` 里把 `video.currentTime` 与 `progress` 强同步（`target = LOOP_START + progress%×区间长`，偏差 >0.3s 就 seek）。静音时 `progress` 停滞/回退到下限，`target` 钉死在某一帧，视频每播到 target+0.3s 就被 seek 回去——画面被钳在 0.3s 窗口内反复横跳（0.5x 静音速下约每 0.6s 一次）。
- **取舍**：**删除 currentTime↔progress 帧同步**，视频在 [1s,3s] 区间自由循环（端点 seek 仍由 `onTimeUpdate` 负责），"声大=快、声小=慢"的因果完全交给 `playbackRate(0.5~2.0)` 表达；拔出时本就切独立 success 视频，无需帧对齐。进度条的"静音回退"保留（紧张感靠进度条体现，不再驱动视频倒退）。
- 遗留：区间端点硬切 → 已在 v1.2 处理（见下）。

## 十二·补2、v1.2 修复（2026-09-07）：循环切换突兀（区间标定 + 逐帧精准跳转）

- **素材时长事实**：`public/radish/pull.mp4` 实测全长 **6.25s**（moov/mvhd `timescale=57600、duration=360000`；视频轨 6.25s、音频轨 6.23s），与 success(8.8s)/ending(7.2s) 同为约 6Mbps 高码率短片，并非长母带。
- **循环窗口标定**：真机看片选定 **1.05s ~ 2.23s**（约 1.18s）为首尾动作最连贯、最适合循环的"用力拔"窗口；早期代码的 1.0~3.0s 是未看片的猜测值。（沟通中一度把"1秒05~2秒23"误听为"1分05~2分23"，解析 MP4 元数据后澄清。）
- **"切换突兀"根因**：循环跳转原本监听 `timeupdate` 事件——该事件约 **250ms 才触发一次**，视频播过 LOOP_END(2.23s) 后要等事件到来才 seek 回起点，实际常播到 ~2.4s 才猛跳回 1.05s：跳变距离大、时机漂移，观感突兀。
- **修复**：循环跳转移到 `pullLoop` 的 **requestAnimationFrame 逐帧检测**（`currentTime >= LOOP_END` 立即 seek 回 `LOOP_START`，60fps 误差 <1 帧），删除 `onTimeUpdate` 函数及模板 `@timeupdate` 绑定；`onVideoMeta` 保留作起点校正。配合用户选定的连贯窗口，接缝基本不可察。
- 后手（未做）：若真机仍觉接缝跳，再上双 video 交叉淡化（crossfade）彻底掩盖；当前 rAF 精准跳转 + 连贯窗口已足够，不预先上复杂度。

## 十二·补4、v1.4（2026-09-07）：取消播放变速，改为恒速循环

- 用户反馈：讲话时 `playbackRate` 随音量加速（0.5~2.0x）让兔子动作滑稽，不要变速。
- 调整：循环双机与单片**恒速 1x 播放**，删掉 pullLoop 里的 `playbackRate = rate` 动态调速；叠化触发点相应固定为 `dur - FADE`（不再随 rate 前移）。
- "声大拔得快"的因果完全由**进度积分**承担：volume 越大 progress 涨越快 → 拔一根萝卜所需的**循环次数越少**（视频本身速度不变，只是少转几圈就拔出）。静音时进度停滞/回退，循环照常匀速转，兔子一直平稳地拔。

## 十二·补5、v1.5（2026-09-07）：音量跳动 + 进度反复退回 30%

- 真机现象：持续朗读时音量条"跳动"，进度涨到 30% 后涨一点又跌回 30%。
- 根因①（跳动）：音量用对称平滑 `0.85旧+0.15新`，升降同速；朗读字间停顿/换气 RMS 瞬间掉底，指针跟着抖。
- 根因②（退回 30%）：静音回退只要 `volume < threshold*0.5` 瞬时成立就触发，且每秒 -18%、下限 30%；朗读一换气瞬时跌破即回退，造成"涨点→停顿→退回 30%"。
- 修复：
  - 音量改**非对称平滑（快上慢下）**：attack `0.5旧+0.5新`（约 2 帧跟上），decay `0.94旧+0.06新`（时间常数约 0.28s，停顿不暴跌）；
  - 回退加 **1.5s 宽限**（连续 90 帧低于阈值一半才开始，`quietFrames` 计数，进 PULLING 重置）+ 回退降速到约 -8%/s；
  - 顺带修 `initMic` 重复调用泄漏：每次开麦前先 stop 旧 micStream、close 旧 AudioContext（"测试麦克风"后再开始会重复调用）。
- 待观察：若讲话时音量峰值本身偏低（音量条到不了黄/红段、进度仍涨得慢），属阈值/增益标定——用齿轮"测试麦克风"看最大音量百分比，据此调低"音量阈值"滑块，不必改代码。
