## 一、消息推送方案

### 交互可行性（结论：可行，且贴合现有模式）

- **完整配置放"个人设置"页**：新增一张「🔔 消息推送」卡片（渠道密钥 + 测试 + 事件开关 + 教程链接），和 AI 助手卡同级同模式。
- **待办页放状态入口**：工具栏右侧一个 chip/按钮——
  - 已配置且开启：显示"🔔 推送已开启（企业微信）"（绿色，点击进设置可改）；
  - 未配置：显示"🔔 开启到期提醒"（粉色高亮，点击打开配置）。
  - 点击行为建议：**弹一个轻量配置对话框**（渠道选择 + webhook 输入 + 测试 + 教程链接 + "更多设置去个人设置"），避免直接跳走打断；也可直接跳设置页锚点。二选一，倾向弹窗快配。
- 新增待办选了截止日期时，若推送已开，给一句轻提示"将在到期当天早上提醒你 📲"。

### 三个推送渠道（服务端发 HTTP，老师只需复制粘贴）

| 渠道 | 老师要拿的东西 | 服务端怎么发 | 备注 |
|---|---|---|---|
| **企业微信群机器人** | 机器人 Webhook 地址（URL 里带 key） | POST URL，body `{"msgtype":"text","text":{"content":"..."}}` | 最简单，**推荐新手**；无需加签 |
| **钉钉群机器人** | Webhook 地址（access_token）+ 可选加签 secret | POST `.../send?access_token=...&timestamp=..&sign=..`，body 同上；加签用 HmacSHA256(secret, timestamp+"\n"+secret) 再 Base64+URLEncode | 安全设置选"加签"才算 sign；选"关键词"则消息须含关键词（可固定带"班主任"等） |
| **Bark**（iOS） | App 里的设备 Key（可选自建服务器地址） | GET/POST `https://api.day.app/{key}/{title}/{body}`（自建换域名） | 只推到自己 iPhone，私密；适合个人提醒 |

- 服务端用 JDK11 自带 `java.net.http.HttpClient`（不引新依赖）；钉钉加签用 `javax.crypto.Mac`。
- 推送失败（网络/密钥错）**静默 catch + 记录日志**，绝不阻断业务；"测试推送"按钮把成功/失败明确反馈给老师。
- 密钥/webhook 同 AI key 处理：**不明文回显**（GET 只回"是否已配置"掩码状态），存 setting。

### 配置存什么（setting 键，per-user）

- `push_enabled`：总开关 '1'/'0'。
- `push_wecom_url`：企业微信机器人 webhook。
- `push_dingtalk_url` / `push_dingtalk_secret`：钉钉 webhook + 加签 secret（可空）。
- `push_bark_key` / `push_bark_server`：Bark key + 自建服务器（可空，默认 api.day.app）。
- `push_events`：JSON 事件开关，如 `{"todo":1,"achievement":1,"leave":1,"score":1,"pet":0}`。
- GET 状态接口只返回各渠道"是否已配置 + 是否启用 + 事件开关"，不返回完整密钥。

### 推送什么（设置里可逐项开关）

| 事件 | 类型 | 本期 | 触发点 |
|---|---|---|---|
| **待办到期/逾期提醒** | 定时 | ✅做，默认开 | 每天早 8:00 定时扫 |
| **学生获得成就/奖牌升级、大满贯** | 定时早报 | ✅做，默认开 | 早 8:00 先 scan 再汇总过去一天新成就推一条 |
| 病假累计预警（达阈值⚠️）/ 新请假单 | 即时 | ⬜留开关位 | 请假登记/病假预警处（后续 hook） |
| 成绩导入完成 | 即时 | ⬜留开关位 | ScoreController 导入返回后（后续） |
| 宠物进化/毕业待播、宠物异常 | 即时 | ⬜留开关位 | 宠物升级/毕业处（后续） |
| 每日早报（今日待办+今日课程数） | 定时 | ⬜留开关位 | 后续 |

> 本期只做前两个（都走早 8:00 定时）；其余事件在 `push_events` 里留键、设置卡片留开关（置灰或标注"即将支持"），后续按同一 `PushService.pushToUser` 接一行即可。

### 早 8:00 定时任务（待办提醒 + 成就早报，同一条 cron）

- 开启 Spring 定时：启动类 `PlatformApplication` 加 `@EnableScheduling`；新建 `service/PushScheduler.java`，`@Scheduled(cron="0 0 8 * * ?")`。
- **定时方法无 HTTP 请求上下文**：不能继承/调用 `BaseController.uid()`（RequestContextHolder 取不到）；改为先 `SELECT DISTINCT user_id FROM setting WHERE k='push_enabled' AND v='1'`，逐个 uid 显式传入 PushService。
- 每个启用用户：
  1. **待办**（`push_events.todo=1`）：查 `done=0 AND due_date IS NOT NULL AND due_date <= CURDATE()`；due=今天列"📋 今日到期"，due<今天列"⚠️ 已逾期 N 条"；汇总成一条。biz_ref = `todo-daily:{yyyy-MM-dd}`（每天一条，天然幂等）。
  2. **成就**（`push_events.achievement=1`）：先调 `achievementScanner.scan(uid)`（幂等，把隔夜新达标的算出来），再查本学期 `student_achievement` 中 `awarded_at >= 现在-26小时` 且**未推过**的记录（LEFT JOIN push_log 反查），汇总"🏅 昨日新成就：小明 劳动能手🥈、小红 大满贯🥇…"。每条成就 biz_ref = `ach:{student_achievement.id}:{tier}`（升级 tier 变 → 新 key 会再推一次；26h 窗口保证老师隔天打开也不漏）。
- 两段都**无内容则不发**；有内容各自一条消息，发到该用户**所有已配置渠道**（都发）。
- **幂等去重**：新增轻量表 `push_log`，发送前按 `(user_id, channel, biz_ref)` 查，已存在则跳过该渠道；发送成功后插入。复用 pet_log 的 biz_ref 幂等思路。

### 推送服务（后端）

- 新建 `PushService`：`pushToUser(uid, title, content, bizRef)`——读该用户 setting，按启用渠道发企微/钉钉/Bark，写 push_log 去重；`testPush(渠道)` 发一条"测试成功 ✅"。
- 各渠道消息拼装 + 签名 + HTTP 发送集中在此；业务代码只调 pushToUser。

## 二、待办页新增区 UI 修复（截图1）

**根因**：`.add-card` flex 一行放 输入框(append 分类, max520) + 日期(160) + 按钮，宽度超出卡片后换行；换行后 `margin-left:10px` 脱离对齐、append 槽/日期/按钮高度与圆角不统一，显得"没对齐、按钮边框乱"。

**修复方向**（实施时定，KISS）：
- 新增区改为整齐的两行或自适应一行：用 `gap` 代替 `margin-left`；输入框 `flex:1`（占满剩余），分类下拉、日期、添加按钮固定宽度；`flex-wrap:wrap` 时所有控件统一高度（同一 size、统一圆角 14px 主题风）。
- 推荐布局：第一行 = 内容输入框（flex:1，分类 select 作为右侧 append 或独立放第二行）；第二行 = 截止日期 + 添加按钮右对齐；或单行 space-between。统一所有控件高度 36~40px、圆角、边框色（用主题 `--el-input` wrapper 样式，避免 append 槽灰块突兀）。
- el-card 内边距与控件对齐：`.add-card :deep(.el-card__body)` flex + gap + wrap。

## 三、设置页"修改密码"卡片大片留白（截图2）

**根因**：`.cards` 两列 grid 默认 `align-items:stretch`，右列"修改密码"卡（内容矮）与左列"个人资料"卡（内容很高）**同一行被拉伸等高**，表单只占顶部，下方整段白卡片空白。

**修复方向**（一行 CSS）：
- `.cards { align-items: start; }`（或 `.candy-card { align-self: start; }`）——卡片按自身内容高度，不拉伸；矮卡片下方露出页面奶油底而非白色卡片，空白感消失。
- 顺带核对：右列"我的学科"卡与左列"我的班级/AI"卡高度差，用 align-items:start 后各卡顶对齐、高度自适应即可，无需重排。

## push_log 表（schema.sql 幂等新增）

```sql
CREATE TABLE IF NOT EXISTS push_log (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id BIGINT NOT NULL,
  channel VARCHAR(16) NOT NULL,        -- wecom / dingtalk / bark
  biz_ref VARCHAR(64),                 -- 幂等键，如 todo-daily:2026-09-03 / ach:123:GOLD
  ok TINYINT DEFAULT 1,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  KEY idx_push_user (user_id),
  KEY idx_push_biz (user_id, channel, biz_ref)
);
```

## 后端接口（新增 PushController，/api/push，照抄 AiController 密钥模式）

- `GET /api/push/config`：返回 `{enabled, events:{todo,achievement}, wecom:{configured}, dingtalk:{configured,hasSecret}, bark:{configured,server}}`；**不下发完整 webhook/key**，只回是否已配置（可附后 4 位掩码）。
- `PUT /api/push/config`：保存 enabled/events/各渠道值；webhook/key 空串=不修改、`__clear__`=清除（同 AI key）。
- `POST /api/push/test` body `{channel}`：向该渠道发一条"🔔 测试成功，班主任工作台推送已连通 ✅"，返回 `{ok,message}`；失败把渠道返回的错误信息透传给老师。
