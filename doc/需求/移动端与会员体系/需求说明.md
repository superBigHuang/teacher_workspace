# 移动端（老师遥控 + 家长端）与 VIP 会员体系 — 需求说明

> 状态：**P0 H5 遥控已交付（2026-09-02，E2E 通过）**；P1 小程序 / P2 VIP 待备案与执照。
> **P1 后端初版（双码绑定/家长接口）已在本地写就但未提交，工程隔离方案见第十一章，待本文档确认后再转入 worktree 开发。**
> 前提确认：个体工商户执照可申请；公网服务器已部署、域名备案中。

## 一、背景与问题

1. **投影遥控场景**：老师在教室用 PC 投影座次表宠物页，但人在教室走动，进化演出目前只能在 PC 上触发/自动弹。需要手机当遥控器：攒着一批进化、择机一键播放，播过的不再播。
2. **家长端缺位**：家长看不到孩子在校的加分/扣分、考勤作业、宠物成长，教育闭环缺一环。
3. **商业化**：系统目前单机单账号使用，需要会员/非会员体系 + 邀请裂变 + 在线收费（20 元/半年、30 元/年），支撑多老师 SaaS 化。

## 二、目标与非目标

**目标**
- 老师手机端：快捷加减分、进化演出遥控播放（待播队列）、拍照上传（皮肤素材优先）。
- 家长端（微信小程序）：微信登录 + 绑定码绑定孩子，只读查看宠物状态、加减分流水、考勤/作业/纪律、评语、成就；微信订阅消息通知。
- VIP：注册送 1 月会员；邀请新用户且新用户录入学生达标后，邀请人 +1 月、新用户 +2 月；首充减 5；邀请人获首单实付 20% 返利；防白嫖。

**非目标（本期不做）**
- 家长端不做任何写操作（不改分、不请假审批）。
- 老师小程序不做重管理（排座、课表编排、成绩导入仍在 PC），只做高频轻操作。
- 不做 App（uni-app 留 App 能力但不发布）。

## 四、方案 A：移动端

### A1. 遥控通道：SSE（不用 WebSocket）

- 方向不对称：**手机只发指令（低频 POST），PC 只收事件**→ SSE 恰好匹配，比 WS 少一半复杂度；浏览器 EventSource 原生自动重连。
- PC：先 `POST /api/remote/ticket` 拿 60 秒一次性 ticket（EventSource 不能设 Authorization 头，避免 token 进 URL 日志），再 `GET /api/remote/events?ticket=xxx` 长连。
- 手机：`POST /api/remote/cmd`（JWT 鉴权），服务器按同 uid 转发给该老师在线的 PC 连接。
- 配对：同账号即同房间（手机 PC 登录同一老师账号），无需配对码。

**指令清单（v1）**

| 指令 | 说明 |
|---|---|
| `evolve.play` / `evolve.playAll` | 播放指定一条 / 全部待播进化（PC 端入队 `enqueueEvolves`，演完照常 evolve-seen） |
| `pet.quickScore` | 手机快捷加减分。**经手机端的评价一律置 evolve_pending**（同异步联动路径），PC 收到 `pets.changed` 静默重拉，升级自动进待播队列，不打断投影 |
| `pets.changed` | 服务器广播事件：PC 重拉 `/pet/pets` 刷新状态 |
| `navigate` | PC 切页（座次表/花名册/工作台） |
| `spotlight` | 高亮某学生座位（找人用） |

教室仪式流：上课中手机随手加减分（升级全部攒队列）→ 投影前手机点"🎬 全部播放"→ PC 连播进化演出。

### A2. 载体分两步走

- **P0 — H5 遥控页（无需任何资质）✅ 已交付**：现有 Vue 工程加 `/m` 移动端路由（大按钮学生网格 + 规则加减分 + 待播队列 + 播放控制）。手机浏览器打开即⽤，免审核免安装。
- **P1 — 微信小程序（原生，2026-09-02 用户定案）**：**微信原生小程序**（WXML/WXSS/JS，不用 uni-app），独立文件夹 + 独立仓库，微信开发者工具开发联调。老师端 = 遥控 + 奖惩拍照 + 微信静默登录；家长端 = 绑定 + 只读 + 图片查看 + 订阅消息。

### A2.5 小程序双码绑定架构（2026-09-02 定案）

**一个小程序、两个入口、PC 端两个二维码**（二维码带 key 标识老师，支撑多老师 SaaS）：

| 码 | 位置 | scene 内容 | 扫码后流程 |
|---|---|---|---|
| 教师码 | PC 个人设置页，长期固定 | `t{uid}` | wx.login 拿 code → **首次要求输账号密码验证身份**（防捡码冒绑）→ 后端校验密码后把 openid 绑到 sys_user.wx_openid、发教师 JWT；之后打开小程序 wx.login 静默直达教师端 |
| 家长码 | PC 个人设置页（班级级，一个码），7 天 ticket 可重生成 | `p{ticket}` | wx.login + getPhoneNumber 授权手机号 → 后端经 ticket 找到老师 uid → 在该老师 `parent_contact` 按手机号匹配 → 建 parent_account + parent_binding（同手机号多个孩子全部绑定）→ 发家长 JWT 直达家长端；匹配不到提示联系老师登记手机号 |

- **双端路由**：小程序启动 wx.login → 后端查 openid：命中 sys_user → 教师端；命中 parent_account → 家长端（列出绑定的孩子）；都没命中 → 引导扫码页。
- **二维码形态**：最终用微信小程序码（wxacode.getUnlimited，scene 传 key，**不依赖备案域名**）；开发期后端 `app.wx.mock=true`（未配置 AppID 时自动生效）用 mock openid/手机号跑通全链路。
- **教师小程序遥控**：小程序无 EventSource，教师端发指令走 POST `/remote/cmd`、状态刷新走 10s 轮询/下拉刷新；PC 端 SSE 通道不变。
- 家长 JWT 带 `type=PARENT` claim，只能访问 `/api/p/**`（按 binding 的 student_id 集合过滤），教师 token 不能访问家长接口，反之亦然。

### A3. 家长端

- **账号**：新表 `parent_account`（wx_openid 唯一）；不进 sys_user。
- **绑定**：以 A2.5 双码定案为准——PC 设置页家长码（班级级 7 天 ticket，可多人扫），家长扫码后微信授权手机号，与老师登记的 `parent_contact` 手机号归一化匹配，自动建 `parent_binding(parent_id, teacher_user_id, student_id, relation)`（同号多孩子一次全绑）。家长是跨 user_id 的只读访客。
- **可见数据**（`/api/p/**` 全部按 binding 的 student_id 集合过滤）：宠物形象/等级/状态标、**加减分流水（pet_log，核心诉求，含奖惩图片，见 A4）**、考勤/作业/纪律/请假、成就徽章、期末评语；成绩由老师设置开关控制是否开放（建议默认关）。
- **订阅消息**：加分/扣分/进化/请假 通知家长（微信一次性订阅，交互中引导授权）。
- 老师小程序身份：sys_user 加 `wx_openid`，首次账号密码登录绑定，之后 wx.login 静默登录。

### A4. 教师手机端：奖惩拍照上传（2026-09-02 用户定案）

- **场景**：PC 上传图片不方便；老师在教室手机加减分时随手拍照（作业未交、违纪现场、表扬瞬间），家长端看到图文而非干巴巴一条扣分。
- **流程**：手机端（H5 `/m` + 小程序教师端）加减分面板支持拍照/相册多选 → 上传走现有 `MultipartFile` 机制落 `uploads/`（返回 URL）→ 评价接口带图片 URL 列表 → 写入 `pet_log.images`（JSON 数组字段，schema 幂等加列）。
- **家长端**：`/api/p/logs` 返回 images，流水列表点开看大图。
- **存储**：本期本地磁盘 + `/uploads/**` 静态映射（现有机制零新增）；后续上量再迁 OSS（P2 之后）。
- 皮肤素材上传降级为 P1 候选（不再优先）。

## 五、方案 B：VIP 会员与邀请返利

### B1. 数据模型

- `sys_user` 加字段：`vip_expire_at`、`invite_code`（注册生成 6 位去混淆码）、`inviter_id`、`balance`（返利余额，仅可购会员不可提现）、`wx_openid`、`phone`、`invite_rewarded`（达标奖励幂等）。
- 新表 `vip_order`（订单：plan HALF/YEAR、amount、status、wx_transaction_id、is_first、paid_at）。
- 新表 `invite_reward`（inviter_id、invitee_id、reward_type MONTH/CASHBACK、amount、related_order_id；`UNIQUE(invitee_id, reward_type)` 幂等）。
- 会员时间统一在 `max(now, vip_expire_at)` 上累加。

### B2. 收费与返利（按题设计算账）

| 场景 | 权益/现金流 |
|---|---|
| 普通注册（无邀请码） | +1 月会员 |
| **邀请码注册** | **+2 月会员（注册即到账，比普通注册多 1 月，制造填码引导）** |
| 邀请达标（新用户绑微信 openid 且录入 ≥10 名学生） | **邀请人 +1 月**（新用户注册时已享 2 月，达标不再叠加） |
| 新用户首充年付 | 30 − 5 = **实付 25**；邀请人获 25×20% = **5 元余额** |
| 新用户首充半年 | 20 − 5 = 实付 15；邀请人获 3 元余额 |
| 续费/非首单 | 原价，无减免无返利 |

- 邀请码注册多给 1 月的防刷分析：多领的 1 月是**自用会员权益、无变现路径**（返利只发生在被邀请人真金白银首充时），刷小号无利可图；邀请人的 1 月奖励仍有"录 ≥10 学生 + 绑微信"门槛后置，刷量成本高。
- 返利只做**一级**、只返**被邀请人首单**、返**平台余额不可提现**——合规无传销风险，且现金锁定在平台内促续费。

### B3. 防白嫖

1. 邀请码**注册时填写、注册后不可补绑**；一人一码。
2. 奖励门槛后置：新用户必须 **wx_openid 已绑定 + 录入 ≥1 个班级且 ≥10 名学生**才发 1+2 月奖励（刷小号不会录 10 个学生）。
3. 一个 openid 只绑一个老师账号；账号密码注册路径领奖前须绑微信/手机验证。
4. 首充减免每账号一次；返利按被邀请人首单幂等发放。
5. 同 IP/设备批量注册记日志风控（弱信号）。

### B4. 功能划分（2026-09-02 用户定案）

**总原则：教师端日常管理免费拉新；宠物养成与家长端是会员卖点。注册即送会员试用期，体验完整。**

- **免费（教师端基础）**：花名册、座次表、值日班委、课程表、待办、考勤/作业/纪律登记、家校沟通记录——日常班级管理全套，核心体验不残。
- **会员**：
  - **宠物养成全套**：座次宠物、进化演出、皮肤与特效主题、H5/小程序遥控、奖惩拍照（A4）；
  - **家长端**：家长码生成、家长绑定与只读查看、奖惩图片同步、订阅消息推送（**付费方是老师**——老师开会员才能开通本班家长查看，家长不付费）；
  - 高级效率：成绩分析与 Excel 导入导出、AI 评语/AI 速记、成就系统。
- **老用户迁移**：上线前已注册账号默认赠送长期会员（如 10 年），不砍已在用的功能。
- gating UI 细节（免费用户座次页宠物位如何降级、会员提示弹窗）P2 实施时设计。

## 十一、工程结构与开发隔离（2026-09-02 提审，待确认）
