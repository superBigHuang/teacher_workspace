# 宠物系统升级 —— 需求分析（纯分析，未改代码）

> 2026-09-04。状态：**决策已确认，可分期开工**。
> 三大块：**A. 宠物独立页**（含本周榜前三登台）／**B. 每日通关·打怪兽**（答题打 Boss）／**C. 答题 PK**（单人 + 按小组）。

## 已确认决策（2026-09-04 拍板）

1. **题库来源**：老师自建题库（分类 + 题目 + 答案 + 难度），不走外部题库；支持手动录入 + Excel 导入。
2. **组队分组**：按**座位列**（seat_assignment.col_no），过道列自动剔除；组长取 `committee.role='组长'`，缺省列内第一人。**PK 开战时快照分组**（`pk_session.snapshot_json`），防止中途换座位导致队伍漂移。
3. **前三名口径**：**本周累计得分** = `pet_log` 中 `score>0` 且本周一 00:00 之后的总和（**不读 `pet.exp`**——商店兑换扣 exp 但不写 pet_log，会造成口径错乱）。
4. **本期范围**：A/B/C 全部出方案，分 P1~P5 五期开发（见末节）；Boss 形象 v1 用 emoji 占位（👾🐲👹🦖🦑），后续可换 AI 绘图素材。
5. **现有素材已够用，无需额外提供**：5 套完整宠物皮肤（candy/catdragon/dragon/firedragon/forest/moonrabbit 各含蛋 + Lv1~5 共 36 张 webp）+ 22 张 Fluent 3D 徽章 PNG（含 medal-1st/2nd/3rd、trophy、crown、gem、sparkles、party、rocket、star 等），完全覆盖领奖台 / 宠物墙 / Boss 胜利特效所需。

## 背景与问题

- 宠物目前嵌在座次表（Seat.vue，1393 行）里，老师是日常用，但学生视角缺一个**"展示舞台"**：同学互相看不见宠物、不知道谁本周最努力。
- 每天通关（抽背诵）当前是纯口头，无系统记录、无加分联动，激励断链。
- 想搞答题 PK（个人抢答 + 小组轮答），需要题目、分组、计分、奖励一套闭环，且要**互动性强、画面热闹**，能吸引低年级学生。

## 现状事实（已核对代码）

- `pet(level 1~5, exp cap 280, graduated_count, evolve_pending, hatched)` 一等公民；`PetService.award(uid, studentId, ruleId, score, source, bizRef, remark)` 是唯一加分入口（自动写 pet_log、biz_ref 幂等）。
- `pet_rule` 已 37 条预置（学习/行为/健康/其他），可停用、可自定义；新增 BOSS_*、PK_* 直接 INSERT，不动老数据。
- 实时通道已有：RemoteHub SSE（`pets.changed / evolve.play / spotlight / navigate`），新增 `boss.* / pk.*` 动作即可。
- 前端路由：MainLayout 子路由已有 `/dashboard /seat /duty /score /comment /roster /parent /timetable /todo /daily /settings`；新增 `/pet /boss /pk` 即可，手机遥控 `/m` 加两张控制卡。
- 数据隔离：`uid()` 走 RequestContextHolder；所有新表带 `user_id` + 索引。
- MySQL 5.7-ish：禁用 CTE/窗口函数；周榜用 `SUM(score) GROUP BY student_id` 即可。

### 领奖台（podium）规则

- **数据源**：本周榜（默认）= `SUM(pet_log.score) WHERE score>0 AND created_at>=本周一 00:00`；切换 tab 改 total_exp / level。
- **台位**：🥇 中央最高（缩放 1.15）、🥈 左、🥉 右；若不足 3 人则空缺显示"虚位以待"。
- **每格内容**：宠物图（未破壳显蛋）+ 学生姓名 + 宠物名 + `本周 +N`（绿色高亮）+ 徽章（👑组长 / 毕业 ×N）。
- **动效**：进入页面 0.6s 从底部升台 + canvas-confetti 金色雨（复用 EvolutionShow 同款）；只播一次，不循环。
- **图片资源**：`badges/medal-1st.png / medal-2nd.png / medal-3rd.png` 挂角落；台顶 `badges/trophy.png`。

### 全员宠物墙

- **卡片字段**：宠物图（按 `pet.level` + `hatched` 选 skin）、学生姓名、宠物名、Lv、本周 +N、exp 进度条（`exp/280`）、角标（👑组长 / 🎓×N 毕业次数 / 🥚孵化中）。
- **排序**：默认 本周得分 desc → 总 exp desc；切 tab 时换口径。
- **筛选 chip**：全部 / 已破壳 / 孵化中 / 本周进步（score>0）。
- **点击卡片**：弹学生宠物详情（皮肤、徽章墙、最近 10 条 pet_log）——复用 Seat.vue 现有 PetDetailDlg 组件。
- **40 人性能**：grid 8 列、卡片用 `transform/opacity` 动画，不开 box-shadow 动画；webp 懒加载 `loading="lazy"`。

### 与现有 Seat.vue 的边界

- Seat.vue 保留：座次格子、宠物小图标（点一下评价）、批量评价、进化演出容器（`data-sid` 锚点）。
- Seat.vue 移除：「🏆 荣誉榜」入口、「🛍 商店」入口 → 搬到 `/pet` 顶部。
- 进化演出继续走 `evolve.play` SSE + EvolutionShow 全屏，**不搬家**；`/pet` 页面同样监听该 SSE（挂载 EvolutionShow），保证老师在大屏任何页都能播。

## 二、B. 每日通关 · 打怪兽 `/boss`

### 玩法循环（老师视角）

```
1. 早读前打开 /m（手机遥控）→ 点 "👾 今日打怪兽"
2. 大屏（教室电脑任意页，或专门 /boss 页）弹出今日 Boss：👾 名字 + HP 100/100
3. 老师手机点 "🎲 出题" → 大屏显示题目（不显示答案）
4. 老师点 "👉 抽人"（随机抽或点名）
5. 学生站起来口头回答
6. 老师手机按  ✅ 通过 / ❌ 未过
   ✅ → 大屏 Boss 被揍一拳，HP -10，学生 +5 成长值（BOSS_PASS）
   ❌ → Boss 咆哮动画，无扣分
7. 反复 3-5；HP 归 0 → 爆炸 + 金色雨 + "击杀者 xxx"
   击杀者 +10（BOSS_KILL），全班 +2（BOSS_KILL_ALL）
8. 24:00 未击杀 → Boss "逃跑"（ESCAPED），次日刷新
```

### Boss 数据

- **每天一只**，`uk(user_id, boss_date)`。
- HP 默认 100，每次 PASS -10（即 10 人通关可击杀）；可调 setting。
- 形象：v1 用 emoji 池 `👾🐲👹🦖🦑🦖👽🤖`，每天随机一只 + 随机名字（"小怪兽阿呜""钢铁大王"等）。
- 状态：`ACTIVE / KILLED / ESCAPED`（次日 0 点定时把昨天 ACTIVE 的置为 ESCAPED——或懒处理：查询时判断 boss_date<今天 且 ACTIVE → 视图为 ESCAPED，不落库。KISS 选后者）。

### 奖励规则（新增 pet_rule 预置）

| rule_code | 分值 | 说明 | biz_ref |
|---|---|---|---|
| BOSS_PASS | +5 | 单次通关 | `boss:{date}:hit:{hitId}` |
| BOSS_KILL | +10 | 击杀者加成 | `boss:{date}:kill:{studentId}` |
| BOSS_KILL_ALL | +2 | 全班同庆 | `boss:{date}:ALL:{studentId}` |

失败 0 分（不扣分，保护积极性）。

### 题库（老师自建）

- `quiz_category`：分类（语文背诵/英语单词/数学口算/科学常识…），icon emoji，可停用。
- `quiz_bank`：question（题干）+ answer（答案，**只给老师看**）+ difficulty 1~3 + use_count + last_used_at（智能避让：30 天内出过的降权）。
- **录入方式**：①手动表单 ②Excel 导入（列：分类/题目/答案/难度）③后续可接 AI 批量生成（留口子）。
- **抽题策略**：选分类 + 难度 → `ORDER BY (last_used_at IS NULL) DESC, last_used_at ASC, RAND() LIMIT 1`（最久没用的优先）。

## 三、C. 答题 PK `/pk`

### 两种模式

**SOLO 个人抢答**（适合全班热身、快速决定名次）
**TEAM 组队轮答**（适合小组对抗、培养协作）

### SOLO 流程

```
老师 /m 发起 → 选分类+难度+轮数(默认10) → 大屏出"PK 即将开始"倒计时 3-2-1
每轮：题目上屏 → 全班口头抢答，老师手机看到第一个举手的名字点他 → 学生口头答
   老师判 ✅+2 / ❌-1 → 大屏记分板实时跳分
10 轮结束 → 前三名登台（复用 /pet 领奖台组件）
奖：🥇+10  🥈+6  🥉+4  参与奖全员+2
```

### TEAM 流程

```
老师 /m 发起 → 系统按 seat_assignment.col_no 快照分组（过道列剔除）
  → 大屏展示分组（每组一列，显示组长）
每轮：题目上屏 → 轮到某组 → 组内 30 秒讨论（大屏倒计时）→ 组长口头回答
   老师判 ✅该组+3 / ❌0（不扣分，鼓励大胆答）
12 轮（默认）→ 排名
奖：🥇冠军组 全员+8  🥈+5  🥉+3  其他+1  每组组长额外+2（leader 辛苦费）
```

SOLO 模式则是 40 名学生名字 + 实时分数排行（横向滚动条或两列 20×2）。

### 分组快照（关键设计）

- **为什么快照**：PK 进行中若触发"随机排座"，列号会变，导致队伍漂移、分数错归属。
- **怎么做**：`pk_session.snapshot_json` 字段，create 时把 `[{colNo, teamName, leaderId, memberIds[]}]` 整个 JSON 落库；整场 PK 全用快照，不查实时 seat_assignment。
- 结束/取消后，座位变化不影响历史 PK 数据。

### DDL

```sql

### 奖励规则（新增 pet_rule 预置）

SOLO：`PK_SOLO_1ST +10 / PK_SOLO_2ND +6 / PK_SOLO_3RD +4 / PK_SOLO_PART +2`
TEAM：`PK_TEAM_1ST +8 / PK_TEAM_2ND +5 / PK_TEAM_3RD +3 / PK_TEAM_PART +1 / PK_TEAM_LEADER +2`

**biz_ref 幂等**：`pk:{sessionId}:{studentId}:{ruleCode}`，PK 取消时已发奖励**不回滚**（KISS；老师若错发可手工扣分）。

                                 → 写 pk_round + 累 pk_member/pk_team.score + SSE pk.judge
POST /api/pk/finish              {sessionId} → 算名次 + 发奖 + status=FINISHED + SSE pk.finish
POST /api/pk/cancel              {sessionId} → status=CANCELLED（不发奖）
GET  /api/pk/history?limit=20    历史场次
GET  /api/pk/detail?sessionId=   单场明细
```

### SSE

- `pk.state`：session 状态变化（创建/开始/结束）
- `pk.round`：新一轮开始（题目 + 答题人/组）
- `pk.judge`：判定结果 + 比分变化
- `pk.finish`：结束 + 名次 + 颁奖动画触发
