# 用户管理（多账号 + 角色 + 注册渠道）需求说明

> 2026-09-16。状态：**开发完成（分支 feature/user-admin），后端接口与双账号 HTTP 走查全部通过，待老师浏览器统一走查**。
> 一句话：admin 登录后有一个"用户管理"页，能看账号列表、新增账号（选角色、选渠道）、重置密码、停用/启用账号。

## 一、背景与目标

- 系统开始给本校其他老师/外部试用者使用（朋友、小红书、同校三个引流渠道），需要在页面上开通和管理账号，不能再直接改数据库。
- 目标：①账号列表可见（账号信息+渠道+状态）②admin 页面新增账号 ③重置密码 ④停用/启用 ⑤账号区分管理员/普通老师。
- 非目标：不做细粒度模块权限（不按菜单/按钮授权）、不做账号自助注册、不做删除账号（只停用）、不做渠道统计报表（v1 仅打标展示）。

## 二、现状盘点（已核实）

1. **账号表 `sys_user`**（schema.sql:6-14）只有：id / username / password_hash / display_name / email / school / created_at。无 role、无 enabled、无渠道字段。初始 admin 由 DataInitializer 幂等播种（BCrypt）。
2. **鉴权链路**：`AuthInterceptor`（common/AuthInterceptor.java:22-42）只验 JWT 真伪，把 uid/username 塞 request attribute；JWT claim 只有 uid+username（JwtUtil.java:45）；Controller 统一用 `BaseController.uid()` 取当前用户。**全系统零权限校验**。
3. **登录**（AuthController.java:50-98）不检查账号状态（因 enabled 列不存在）；只有改自己密码 `/auth/change-password`、改自己资料，无任何用户 CRUD/注册接口（自助注册已物理移除）。
4. **数据隔离已做好**：student/pet/score/timetable/setting 等全部业务表带 `user_id` 且读 SQL 均按 uid 过滤，新账号天然看不到别人数据。全局共享表仅 4 张：period（节次模板）、quick_note_rule（速记词）、school_dict（学校名录）、内置 pet_skin/achievement_def。
5. **新账号播种有现成方法**：`UserDataSeeder.seedIfEmpty(uid, name)`（config/UserDataSeeder.java:21），目前只 admin 启动时调用，建号时直接复用。
6. **前端**：菜单硬编码在 `MainLayout.vue:174` 的 navs 数组，无角色条件渲染先例；登录存 localStorage 三个 key（token/displayName/username），无 role；`/auth/me` 返回 username/displayName/email/school。列表+弹窗+行操作范式照搬 `views/QuizManage.vue`。

## 三、方案设计

### 3.1 角色模型（两档，KISS）

| 角色 | 能做什么 |
|---|---|
| ADMIN 管理员 | 全部业务功能 + 用户管理页；初始 admin 固定此角色 |
| TEACHER 普通老师（新增默认） | 全部业务功能，看不到/进不了用户管理 |

不做菜单级、按钮级细分权限；将来真有需要再把 role 扩成权限表。"停用"是独立状态不是角色。

### 3.2 数据库改动（sys_user 加 4 列，DataInitializer.ensureColumn 幂等迁移）

```sql
ALTER TABLE sys_user ADD COLUMN role VARCHAR(16) NOT NULL DEFAULT 'TEACHER';   -- ADMIN/TEACHER
ALTER TABLE sys_user ADD COLUMN enabled TINYINT NOT NULL DEFAULT 1;            -- 1启用 0停用
ALTER TABLE sys_user ADD COLUMN source VARCHAR(16) NULL;                       -- friend/xhs/school，admin 为 NULL
ALTER TABLE sys_user ADD COLUMN last_login_at DATETIME NULL;                   -- 最近登录时间
```

迁移后把现有 admin 行 `UPDATE SET role='ADMIN' WHERE username='admin'`。

### 3.3 后端改动

1. **AuthInterceptor 每请求加一次主键查询** `SELECT role, enabled FROM sys_user WHERE id=?`：不存在/enabled=0 → 401（body 标"账号已停用"）；role 塞 request attribute。理由：主键查询开销可忽略，换来旧 token 全兼容（不用改 JWT）、停用即时生效、接口鉴权有据。放行路径不变（login/captcha/SSE）。
2. **`BaseController` 加 `requireAdmin()`**：非 ADMIN 抛 403。
3. **新增 `AdminUserController`（/api/admin/users，每个方法开头 requireAdmin）**：
   - `GET /api/admin/users`：账号列表（id/username/displayName/role/enabled/source/createdAt/lastLoginAt），账号量小不分页；
   - `POST`：新增账号。入参 username（唯一校验，409 提示）、displayName、初始密码（默认 123456 可改）、role（默认 TEACHER）、source（friend/xhs/school 三选一）；BCrypt 入库后调 `UserDataSeeder.seedIfEmpty` 播种默认班级等数据；
   - `POST /{id}/reset-password`：重置为 123456（或入参指定），返回新密码；
   - `PUT /{id}/status`：启用/停用切换；
   - `PUT /{id}/role`：改角色。
   - **自我保护红线**：不能停用自己、不能把自己降为 TEACHER（后端硬校验，防管理员把自己锁死）；不提供删除接口；admin 账号不可被停用/降级（按 username='admin' 或 id 判定）。
4. **登录**（AuthController）：通过后 UPDATE last_login_at；登录 SQL 加 enabled=1 条件，停用账号返回"账号已停用，请联系管理员"。
5. **登录响应与 `/auth/me` 增加 role/enabled/source**，供前端控菜单。

### 3.4 前端改动

1. 新增 `views/Users.vue`（照 QuizManage.vue 范式）：
   - 表格列：账号、显示名、角色（标签）、渠道（朋友/小红书/同校 中文映射）、状态（启用/停用开关或标签）、创建时间、最近登录、操作；
   - 操作：重置密码（二次确认 → 提示新密码）、停用/启用（二次确认）、角色下拉切换；
   - 新增弹窗：账号*、显示名*、初始密码（默认 123456 可改）、角色下拉（默认"普通老师"）、渠道下拉（朋友/小红书/同校，必选）。
2. `router/index.js`：加 `/users` 子路由；beforeEach 加非 admin 访问 /users 重定向 /dashboard（防直接输 URL）。
3. `MainLayout.vue`：navs 中"用户管理"项 `v-if="isAdmin"`；isAdmin 来自 /auth/me 返回的 role（刷新页面也对）。
4. `Login.vue` / MainLayout：localStorage 增存 role（沿用现有 key 模式）；401/停用提示沿用 http.js 拦截。

### 3.5 渠道枚举

`friend=朋友介绍` / `xhs=小红书` / `school=同校老师`。仅建号打标 + 列表展示，v1 不做统计报表（管理页顶部可顺手显示各渠道人数，实施时看成本决定，非必须）。

## 四、影响范围与风险

- **改动面**：schema 迁移（DataInitializer）、AuthInterceptor、AuthController、BaseController、新增 1 个 Controller + 1 个前端页面、router/MainLayout/Login 小改。不动任何业务 Controller 的 SQL（user_id 隔离已就绪）。
- **全局共享表**：period 节次模板、quick_note_rule 任何登录老师都能改，会互相影响。多老师真实使用前应收为"仅 ADMIN 可写"，**本次不做，列为已知项**。
- `homeroomClassId()` 多处在配置缺失时兜底 `return 1L`（RosterController:41 等）：建号时必须走 seedIfEmpty，避免新账号数据挂到 class_id=1（查询仍带 user_id 不会泄露，但语义混乱）。
- 停用即时生效（拦截器查库方案），无 token 黑名单负担。

## 五、验收标准

1. 普通老师登录：侧边栏无"用户管理"，手输 /users 被跳回工作台；调 /api/admin/users 返回 403。
2. admin 登录：可见用户管理页；列表正确显示全部账号与角色/渠道/状态/时间。
3. 新增账号（普通老师+小红书渠道）：用该账号登录，看到的是自己的空班级（非 admin 的 40 个学生），可正常排座/建学生/加宠物等全部业务功能。
4. 重置密码：该账号用新密码可登录，旧密码失效。
5. 停用：被停用账号当前请求即 401、登录提示"账号已停用"；启用后恢复。
6. admin 不能停用/降级自己（按钮禁用或后端 400）；系统无删除账号入口。
7. admin 老 token（升级前签发）不强制重新登录即可用。

## 六、已确认决策（2026-09-16 拍板）

1. ✅ 角色两档：ADMIN / TEACHER，业务功能无差异，仅差用户管理入口。
2. ✅ 初始密码与重置密码统一 **123456**（登录后可在设置页自行修改）。
3. ✅ 渠道建号时**必选三选一**：朋友 / 小红书 / 同校。
4. ✅ 账号**只停用不删除**，业务数据永久保留。
