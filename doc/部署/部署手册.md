# 班主任工作平台 —— 服务器部署手册

> 适用服务器：Ubuntu 24.04 x86_64（示例：124.221.186.190）
> 部署方式：脚本化部署，后端 systemd 常驻 + nginx 托管前端，零代码改动。

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 17（Temurin） | vfox 管理，路径 `~/.vfox/sdks/java` |
| Maven | 3.9+ | vfox 管理，阿里云镜像 |
| Node.js | 18+（实测 26） | vfox 管理，npm 用 npmmirror 镜像 |
| MySQL | 8.x | apt 安装，root 密码 `root`（与 application.yml 一致） |
| nginx | 任意 | apt 安装，托管前端 dist + 反代 /api |

数据库 `teacher_workspace` 由后端首次启动时**自动建库建表并写入初始数据**，无需手工初始化。

## 2. 目录结构（服务器）

```
/opt/teacher_workspace/
├── app/              # git 仓库（git clone 自 Gitee）
├── application.yml   # ★ 服务器外部配置（线上专属，不进 git；见 §8）
├── backend.jar       # 后端可执行 jar（build.sh 从 app/backend/target 复制，固定名）
├── dist/             # 前端静态文件（build.sh 从 app/frontend/dist 复制，原子替换）
├── uploads/          # 本地上传文件（自定义皮肤图片，不进 git，备份需单独拷贝）
└── logs/
    └── backend.log   # 后端日志（systemd 重定向）
```

- 后端服务：systemd 单元 `teacher-backend`，端口 **8088**
- 前端：nginx 站点 `/etc/nginx/conf.d/teacher-workplatform.conf`，端口 **80**
- 接口反代：nginx `/api/` → `http://127.0.0.1:8088`（后端接口本身带 /api 前缀）

## 3. 首次部署

```bash
# 0. 前置：服务器 SSH 公钥需添加到 Gitee（设置 → SSH 公钥）
#    ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519 && cat ~/.ssh/id_ed25519.pub

# 1. 克隆仓库（SSH 方式）
git clone git@gitee.com:superBigHuang/teacher_workspace.git /opt/teacher_workspace/app

# 2. 执行一键初始化（装 MySQL/nginx、注册服务、构建、启动）
bash /opt/teacher_workspace/app/scripts/deploy/setup.sh
```

浏览器访问 `http://<服务器IP>/`，登录密码见项目 README。

> 云服务器需在**安全组/防火墙放行 80 端口**。

## 4. 运维脚本

脚本均在 `scripts/deploy/` 目录下：

| 脚本 | 作用 | 何时用 |
|---|---|---|
| `setup.sh` | 首次初始化：装依赖、克隆、注册服务、构建、启动 | 只跑一次 |
| `build.sh` | 打包后端 jar + 构建前端 dist | 手动构建 |
| `update.sh` | **git pull → build → restart 一条龙** | 日常发布 |
| `start.sh` | 启动后端 + nginx | 开机后手动启动（已配开机自启，一般不用） |
| `stop.sh` | 停止后端 + nginx（不动 MySQL） | 临时停机 |
| `restart.sh` | 重启后端 + 重载 nginx | 改配置/发布后 |
| `status.sh` | 服务状态、端口监听、HTTP 探测 | 排障 |
| `logs.sh` | 查看后端日志，`logs.sh 200` 看最近 200 行 | 排障 |
| `ssl.sh` | 申请 Let's Encrypt 证书、配 HTTPS（80 跳 443）、开自动续期 | **域名备案通过后执行一次** |

常用命令：

```bash
cd /opt/teacher_workspace/app/scripts/deploy

bash update.sh      # 发布最新代码
bash status.sh      # 看状态
bash logs.sh -f     # 跟踪日志（Ctrl+C 退出）
sudo systemctl restart teacher-backend   # 也可直接用 systemd
```

## 5. 日常发布流程

1. 代码推送到 Gitee master 分支；
2. 服务器执行 `bash scripts/deploy/update.sh`；
3. `bash status.sh` 确认两个 HTTP 探测均正常。

前端构建产物采用"先构建到 dist.new 再原子切换"，发布过程中不会出现半成品页面。

## 7. 域名与 HTTPS（已完成，2026-09-11）

服务器在腾讯云**大陆机房**，用域名提供网页服务必须先完成 ICP 备案，否则 80/443 会被腾讯云拦截（重定向到 `dnspod.qcloud.com/static/webblock.html` 阻断页）。IP 直连不受影响。

**当前域名（已备案、已配 HTTPS）**：`www.novastarhub.cn`（主），裸域 `novastarhub.cn` 一并签证书并 301 跳到 www。旧域名 `teach.pagekithub.com`、图床域名 `easyimagehub.duckdns.org` 与 IP 直连仍走 80 default server。

**证书**：Let's Encrypt，webroot 方式签发（验证目录 `/var/www/certbot`，nginx 各 80 server 都保留了 `/.well-known/acme-challenge/` location）：
```bash
export https_proxy=http://127.0.0.1:7890 http_proxy=http://127.0.0.1:7890   # 出站到 LE API 走 mihomo
certbot certonly --webroot -w /var/www/certbot \
  -d www.novastarhub.cn -d novastarhub.cn \
  --non-interactive --agree-tos --register-unsafely-without-email --cert-name novastarhub
```
证书 `/etc/letsencrypt/live/novastarhub/{fullchain,privkey}.pem`，90 天。`certbot.timer` 自动续期；因是 certonly（非 --nginx 插件），已装 deploy hook `/etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh`（续期成功后 `nginx -t && systemctl reload nginx`）。

**nginx 4 个 server**（配置文件同前；图床与业务共存，改动务必整文件备份）：
1. `listen 80; server_name www.novastarhub.cn novastarhub.cn` → 301 `https://www`（acme location 除外）；
2. `listen 443 ssl http2; server_name novastarhub.cn` → 301 `https://www`；
3. `listen 443 ssl http2; server_name www.novastarhub.cn` → 班主任系统全套（root dist、/api、/uploads、/boss、/radish、SPA；/api、/uploads 额外传 `X-Forwarded-Proto $scheme`）；
4. `listen 80 default_server; server_name teach.pagekithub.com 124.221.186.190 localhost easyimagehub.duckdns.org` → 图床 + IP 直连，**不跳转**。

> ⚠️ **不要直接跑 `scripts/deploy/ssl.sh`**：它会 `sed` 把 `server_name` 整体替换成 env.sh 里的旧域名 `teach.pagekithub.com`（`SERVER_NAME` 默认值），冲掉图床域名、IP 和新域名，且 certbot --nginx 会在唯一 server 块上加 80→443 跳转，连带图床/IP 也被跳。证书续期/加域名用上面的 certbot webroot 命令手工做。
>
> nginx 1.24 用旧语法 `listen 443 ssl http2;`，不支持 1.25.1+ 的独立 `http2 on;` 指令。
>
> 公网前置：安全组放行 443（22/80/443）。备案号前端已在登录页/主布局/手机遥控页底部悬挂并链接 `https://beian.miit.gov.cn`（提交 `25e0ea9`）。

**源站基础加固（2026-09-13，隐藏 IP/防扫描）**：让网站只能经域名访问，拿着真实 IP 打不开：
- **禁 ping**：`echo 'net.ipv4.icmp_echo_ignore_all=1' > /etc/sysctl.d/90-disable-icmp-echo.conf && sysctl -w net.ipv4.icmp_echo_ignore_all=1`（立即+重启持久；不影响 22/80/443 TCP）。
- **拒绝直连 IP/陌生 Host**：nginx 加两个 default server——80 `server_name _; return 444;`（直接断连）、443 `ssl_reject_handshake on;`（陌生 SNI 拒绝握手，1.19.4+ 支持，1.24 可用）。原 80 块去掉 `default_server` 与公网 IP，`server_name` 只留 `easyimagehub.duckdns.org localhost 127.0.0.1`（本机回环仍 200，供 update.sh/status.sh 健康探测；图床不受影响）。
- **其他**：`server_tokens off;`（响应头/错误页隐藏版本）；`ssl_protocols TLSv1.2 TLSv1.3` 统一写在 `/etc/nginx/nginx.conf` http 块（**勿在 conf.d 再写，会 duplicate value 告警**；`listen ... http2` 同一 443 socket 只在一个 server 声明，否则 protocol options redefined 告警）。配置备份 `teacher-workplatform.conf.bak.harden.*`、`nginx.conf.bak.harden`。
- 验证：公网 `curl http://124.221.186.190/` 与 `https://IP -k` 均 000、ping 不通；`https://www.novastarhub.cn` 200、协商 HTTP/2、TLS1.0 被拒。
- 局限：`nslookup/ping 域名` 仍会显示解析到的真实 IP（DNS 必须指向源站，无法隐藏）；要连真实 IP 也藏起来需再上 CDN（见本节历史方案讨论）。

## 8. 服务器外部配置（线上专属，不进 git）

数据库密码、JWT 密钥、**大模型 API Key / 模型名**等敏感与环境配置，不放在项目代码里，由服务器上一份独立外部配置维护：

- 位置：`/opt/teacher_workspace/application.yml`（与 `backend.jar` 同目录）
- 加载：Spring Boot 启动时自动加载，**优先级高于** jar 内 `application.yml`，同名属性以外部文件为准
- 隔离：文件在 git 仓库（`app/`）之外，`update.sh` 只替换 jar/dist，**不会覆盖它**；重跑 `setup.sh` 也不生成它
- 权限：`chmod 600 root:root`（含密钥）
- 改后生效：`systemctl restart teacher-backend`

当前外部配置内容：

| 配置项 | 值 / 说明 |
|---|---|
| 数据库 | root/root（与部署一致） |
| `app.jwt.secret` | openssl 随机 64 字节（线上专属；更换后所有账号需重新登录一次） |
| `app.upload-dir` | `/opt/teacher_workspace/uploads`（绝对路径） |
| `app.pet.dev-hatch` | `false`（生产关闭测试破壳） |
| `app.trust-proxy` | `true`（nginx 单跳反代后采信代理头，失败计数/锁定按真实客户端 IP；见下方说明） |
| `ai.defaults.base-url` | `https://chunfeng.mentalout.top`（OpenAI 兼容 / newapi 渠道） |
| `ai.defaults.api-key` | 渠道 Key（明文仅存本文件） |
| `ai.defaults.model` | `gpt-5.4`（见下方说明） |

**`app.trust-proxy`（nginx 反代必开，2026-09-09 已上线生效）**：登录三道闸门（连续失败 3 次要验证码、5 次锁 10 分钟，账号+IP 维度、30 分钟窗口；统一"账号或密码错误"文案防枚举）。线上在 nginx 之后，后端直连看到的来源全是 127.0.0.1，不开此开关会退化成按账号全局计数。开启后后端取 `X-Forwarded-For` **末段**（nginx 单跳追加的直连地址，客户端伪造首段无效）。已在外部文件置 `true`，提交 `6d46085` 上线。

> **安全前提：8088 后端端口绝不能对公网开放。** `trust-proxy=true` 会采信 XFF，若攻击者能绕过 nginx 直连 8088，即可自带 XFF 伪造 IP 绕过失败计数。当前腾讯云安全组未放行 8088（公网 `curl 124.221.186.190:8088` 连接失败），只经 nginx 80 暴露，安全。换机/改安全组时务必只放行 22/80(/443)。
>
> **生效判定法**（开关 true/false 在经 nginx 时都是 127.0.0.1，无法区分）：在服务器本机**直连后端** `curl -X POST 127.0.0.1:8088/api/auth/login` 用假账号错 3 次（第 3 次返回 `needCaptcha:true`），第 4 次加头 `-H "X-Forwarded-For: 5.5.5.5"`——返回普通错误（`needCaptcha:false`）即 `true` 生效（采信了末段新 IP）；仍要验证码即 `false`。再经 nginx 带同样伪造头，应仍要验证码（末段被 nginx 钉成 127.0.0.1）。

**大模型模型名（2026-09-02 修复）**：jar 内默认 `gpt-5.4-mini` 在该渠道无可用通道（`/api/ai/test` 返回 503 `model_not_found`）。该渠道 `/v1/models` 实际可用对话模型为 `gpt-5.4`、`gpt-5.5`、`gpt-5.6-terra`、`gpt-5.6-sol`、`gpt-5.3-codex-spark`（`gpt-image-2` 为画图模型）。外部配置已改用 `gpt-5.4`，`/api/ai/test` 返回「连接正常」。换模型只改外部文件 `ai.defaults.model` 后重启；各老师也可在页面「AI 设置」里单独覆盖默认。

> ⚠️ **安全**：jar 内 `application.yml` 仍带一个默认 Key 且已随 git 推送到 Gitee（视为已泄露）。建议到渠道商后台轮换该 Key，新 Key **只填服务器外部文件**，不要再提交进仓库。
>
> **备份/迁移**：需单独拷贝 `application.yml` 和 `uploads/` 目录（两者都不随 git）。

验证外部配置是否生效：把 `ai.defaults.model` 临时改成哨兵值 → 重启 → 登录后 `GET /api/ai/config` 应显示该哨兵值（2026-09-02 已用此法确认外部文件 100% 被加载）。

## 9. 常见问题

- **80 端口访问不了**：检查云安全组是否放行 80；`systemctl status nginx`。
- **后端起不来**：`bash logs.sh 200` 看日志；多为 MySQL 未启动或密码不符（`mysql -uroot -proot -e "SELECT 1"` 验证）。
- **数据库连接**：配置在 `backend/src/main/resources/application.yml`（root/root），部署脚本不改代码；如需改密码，同步改 MySQL 与该文件。
- **JWT 密钥**：application.yml 中 `app.jwt.secret` 为默认值，正式对外使用前建议更换。
- **构建慢**：Maven 走阿里云镜像、npm 走 npmmirror，首次构建需下载依赖，后续有缓存。
- **上传文件大小限制**：nginx 与后端均为 20MB，调整需同时改 nginx 配置与 application.yml。
- **内置宠物图片不显示（/pets/*.webp 裂图）**：内置皮肤图片在 `frontend/public/pets/`，build 时进 dist，**必须先 git 提交推送再在服务器跑 `update.sh`**（git pull → 重新 build → 原子切 dist）；文件未提交或 dist 未更新时，nginx `try_files` 回退返回 index.html，浏览器拿 HTML 当图片解码即裂图。验证：`curl -I http://localhost/pets/dragon_1.webp` 应返回 `200` 且 `Content-Type: image/webp`（返回 text/html 即 dist 缺文件）。
- **自创宠物皮肤图片不显示（/uploads/ 裂图，2026-09-02 修复）**：自创皮肤上传到后端 `uploads/` 目录经 `/uploads/**` 访问，但 nginx 只反代了 `/api/`，`/uploads/` 被 SPA 回退吃掉。修复：nginx 配置（80 和 443 两个 server 块都要）加：
  ```nginx
  location /uploads/ {
      proxy_pass http://127.0.0.1:8088;
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
  ```
  模板 `scripts/deploy/nginx-teacher.conf` 已含此段；线上改完 `nginx -t && systemctl reload nginx`。注意 uploads/ 目录在服务器本地（不随 git），备份/迁移时需单独拷贝。
- **拔萝卜大屏 /radish 麦克风被浏览器拦（2026-09-05 上线）**：浏览器 `getUserMedia` 只在 **HTTPS 或 localhost** 下可用。线上域名 + 纯 HTTP 时，打开 `/radish` 点"开始"会立刻报"需要麦克风权限"，nginx 的 `location /radish` 加什么都没用——**唯一解是给域名配 HTTPS 证书**：
  1. 装 certbot：`sudo apt install certbot python3-certbot-nginx -y`
  2. 一键签发：`sudo certbot --nginx -d your.domain.com`（自动改 nginx 配置加 443 server、续期 timer 自动装）
  3. 80 → 443 跳转：certbot 默认已加；若手工配，80 server 里 `return 301 https://$host$request_uri;`
  4. 防火墙/安全组放行 443
  5. 验证：`curl -I https://your.domain.com/radish` 返回 200；浏览器地址栏锁图标绿色；打开 `/radish` 点"开始"应弹麦克风授权而非报错。
  素材 `intro.mp4 / loop.mp4 / pullout.mp4 / success.mp4 / ending.mp4` 在 `frontend/public/radish/`，build 后随 dist 一起发布，无需 nginx 特殊配置。
- **拔萝卜视频首次播放像在"下载"、文字先出影片晚到（2026-09-13 修复）**：localhost 开发无感、线上才出现。根因有二：① 5 个 MP4 的 moov 索引原子都在文件**尾部**，浏览器起播必须先读到 moov，线上高延迟弱网下近似"整个文件下完才出第一帧"；② intro/pullout/success/ending 是播放瞬间才赋 src，封面页没有预取。仓库侧已修复：5 个 mp4 全部用 `ffmpeg -c copy -movflags +faststart` 重制（moov 前置、边下边播、无损）；加载策略为**分级预取 + READY 门控**——封面期先下 intro/pullout（loop 由页面 video 自身预取），READY"听安静声"期间等 3 个核心视频全部 canplaythrough 才进入游戏（页面有 n/3 就绪提示，20s 超时兜底强进），通过后再后台下 success/ending。**发布必须 git 推送后在服务器跑 `update.sh` 重新 build**（视频在 public/ 下进 dist，旧 dist 不会自动更新）。
  - 可选加固：给 nginx 加 mp4 缓存头，同一台大屏电脑第二次上课直接走本地缓存。在 80 和 443 两个 server 块、`location /` **之前**加：
    ```nginx
    location ~* \.mp4$ {
        expires 7d;
        add_header Cache-Control "public";
        access_log off;
    }
    ```
    线上手工添加（模板 `scripts/deploy/nginx-teacher.conf` 暂未含此段），改完 `sudo nginx -t && sudo systemctl reload nginx`。验证：`curl -I https://你的域名/radish/loop.mp4` 响应头含 `Cache-Control: max-age=604800`，且文件开头很快返回（moov 已在头部）。
  - 后手：若学校出口带宽小、success.mp4（1080p/约 6Mbps，7MB）边下边播仍卡，再对素材降码率（体积减半，投影动画观感基本无损）：`ffmpeg -i in.mp4 -vf scale=1280:-2 -c:v libx264 -b:v 2.5M -c:a aac -movflags +faststart out.mp4`。
- **大屏页面 /boss、/radish 打开 403（前端路由与静态资源目录同名，2026-09-08 修复）**：`frontend/public/boss/`（怪兽图）、`frontend/public/radish/`（视频）build 后成为 dist 下真实目录，与前端路由 `/boss`、`/radish` 同名。nginx 收到 `/boss` 发现磁盘是目录，先 301 到 `/boss/`，再按目录取 index.html——目录无 index 且 autoindex 关闭即 **403**，不走 SPA 回退（`/pet` 不受影响：宠物图在 `/pets/`，不与路由同名）。修复：server 块加精确匹配强制回退 SPA（`=` 精确匹配优先级最高，`/boss/*.png` 等资源走前缀匹配不受影响）：
  ```nginx
  location = /boss    { try_files /index.html =404; }
  ```
